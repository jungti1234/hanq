# 한Q 개발 및 유지보수 안내

직접 빌드하고 코드를 수정하는 개발자를 위한 안내다. 제품 소개·설치·사용법·지원 환경은 [README](../README.md), 이용 조건은 [LICENSE](../LICENSE)를 참고한다.

## 로컬 빌드

macOS에서 Swift 컴파일러를 포함한 Xcode Command Line Tools가 필요하다. 실행 중인 한Q를 종료한 뒤 프로젝트 루트에서 실행한다.

```sh
bash scripts/build-app.sh
```

[빌드 스크립트](../scripts/build-app.sh)는 컴파일, 자동 검사, plist·선택한 코드 서명 검증을 마친 뒤 `build/HanQ.app`을 생성한다. 기존 앱이 있으면 `.build/hanq/backups/`에 보관하고 교체하며, 실행 중인 앱은 교체하지 않는다. 새 앱을 실행해 테스트하기 전에 아래 권한 사전 체크를 완료한다.

일반 앱은 `-O -whole-module-optimization`으로 빌드하며 런타임 안전 검사를 제거하는 `-Ounchecked`는 사용하지 않는다. `--development`는 기존 최적화 없는 컴파일을 유지한다. 번들의 `HanQBuild.json`에 최적화 옵션을 기록한다. 성능 비교에서는 제품과 도구의 컴파일 옵션을 맞추고 소스 변경과 컴파일 옵션의 효과를 구분한다.

앱 버전은 `version.env`에서 읽으며 변경 규칙은 [버전 관리](VERSIONING.md)를 따른다. 변경 내용·공개 상태에 맞는 버전과 변경 이력을 함께 갱신한다. 문서 수정이나 동일 입력의 재빌드만으로 번호를 올리지 않는다. 배포 대상·번들 ID는 빌드 스크립트에서 관리하고 컴파일 아키텍처는 arm64로 고정한다. 기존 설치를 업데이트할 때는 번들 ID와 앱 경로를 유지하고 사용자 설정이 보존되는지 확인한다.

### 동일 인증서로 빌드하기

빌드 간 권한 유지를 위해 0.3.0부터 동일 자체 서명 인증서를 사용한다. 후속 빌드와 배포 준비에도 같은 인증서를 명시한다. 옵션·환경변수를 생략한 기본 빌드는 ad-hoc이므로 인증서가 자동 적용된다고 가정하지 않는다. 인증서 서명은 키체인에 보관한 코드 서명 인증서의 40자리 SHA-1 지문을 명시한다. 이름은 이름이 같은 인증서를 잘못 선택할 수 있어 허용하지 않는다.

```sh
bash scripts/build-app.sh --candidate --signing-identity <인증서의-40자리-SHA1>
# 반복 빌드에서는 같은 지문을 HANQ_SIGNING_IDENTITY 환경변수로 지정할 수 있다.
python3 scripts/sign-app.py --inspect build/candidate/HanQ.app
HANQ_SIGNING_IDENTITY=<인증서의-40자리-SHA1> python3 scripts/test-code-signing.py
```

지문은 공개 식별값이며 개인키가 아니다. 개인키는 로그인 키체인 등 안전한 저장소에 보관하고 빌드마다 인증서를 새로 만들지 않는다. 키체인 접근 승인은 macOS가 요청할 수 있다. 인증서가 없거나 서명·검증에 실패하면 빌드를 중단하며 ad-hoc으로 자동 대체하지 않는다. 지정하지 않은 환경에서의 기본 ad-hoc 빌드와 인증서 빌드를 혼용하지 않는다. 인증서 분실·교체 시 기존 권한이 유지된다고 가정하지 않는다.

sign-app.py는 실제 인증서 지문과 코드 식별 조건을 확인한다. 내장 Sparkle의 기존 서명은 보존하며 Developer ID·공증이나 시스템 전체 인증서 신뢰 설정을 대신하지 않는다. test-code-signing.py는 내용이 다른 두 앱의 코드 해시 차이·같은 식별 조건·교차 검증, ad-hoc 앱 거부, 인증서 누락과 변조 거부를 검사한다. 실제 TCC 권한 유지나 물리 키 검증은 별개다.

Sparkle 시험은 기존 prepare-update-e2e.sh에 같은 HANQ_SIGNING_IDENTITY를 전달한다. 독립 시험 폴더는 `/private/tmp` 아래의 `HANQ_UPDATE_E2E_ROOT` 절대 경로로 지정하고 해당 폴더에서 로컬 서버를 먼저 실행한다. 시험 키는 종료 후 삭제한다. 공개 피드·운영 업데이트 키는 변경하지 않는다.

### 새 빌드 테스트 전 손쉬운 사용 권한 사전 체크

공개 0.2.0과 인증서를 지정하지 않은 ad-hoc 빌드에서는 이전 빌드의 손쉬운 사용 권한이 새 빌드에 이어지지 않을 수 있다. ad-hoc 빌드·인증서 변경·미검증 경로에서 실제 앱·입력 테스트를 시작하기 전에는 다음 초기화 절차를 따른다. 검증된 동일 인증서·동일 경로의 후속 빌드는 아래 권한 재사용 검사로 대체할 수 있다. 후보 생성과 권한이 필요 없는 자동 검사만 수행하는 단계에는 적용하지 않는다.

[테스트 준비 도구](../scripts/prepare-app-test.py)가 CUI로 준비와 권한 검사를 수행하고, 사용자는 GUI에서 권한을 승인한다. 다음 명령은 계획 확인과 실제 준비를 구분한다. 후보·설치본은 `build/HanQ.app` 대신 이번에 테스트할 정확한 앱 경로를 지정한다.

```sh
# 종료·초기화·실행 없이 앱 확인과 계획 출력
python3 scripts/prepare-app-test.py prepare build/HanQ.app --dry-run

# 기존 한Q 종료·한Q 권한 초기화·새 앱 실행·설정 열기
python3 scripts/prepare-app-test.py prepare build/HanQ.app
```

- [ ] CUI: 실행 경로와 번들 ID가 확인된 기존 한Q 및 그 보조 프로세스를 종료하고 잔여 프로세스가 없는지 확인한다. 종료가 확인되지 않으면 다음 단계로 진행하지 않는다.
- [ ] CUI: `tccutil reset Accessibility taek.in.hanq`로 한Q의 권한 결정만 초기화한다. 이는 GUI 목록의 `−` 삭제를 확인한 것과 다르다. 기존 항목 혼선이 남으면 GUI에서 기존 한Q를 제거한다.
- [ ] CUI: 앱의 경로·버전·빌드 번호·서명을 확인한 새 `HanQ.app`을 LaunchServices로 실행해 권한 요청을 표시하고 손쉬운 사용 설정을 연다. 목록에 없다면 GUI의 `+`로 도구에 표시된 정확한 앱을 추가한다.
- [ ] GUI 승인 후 CUI 확인: 시스템 설정 → 개인정보 보호 및 보안 → 손쉬운 사용에서 해당 한Q를 ON으로 승인하고, 준비 도구가 출력한 `python3 …/prepare-app-test.py check …/record.json` 명령을 그대로 실행한다.

`prepare`는 앱을 빌드하거나 교체하지 않으며, 사용자 승인 완료를 자동으로 기록하지 않는다. 기록은 기본적으로 `.build/hanq/test-preflight/<실행별 ID>/record.json`에 생성하며, `--output`으로 새 디렉터리를 지정할 수 있다. 기존 기록 디렉터리는 덮어쓰지 않는다. `--dry-run`은 기록을 생성하거나 네 단계 완료로 세지 않는다.

`check`는 권한을 초기화하거나 앱을 종료하지 않고, 준비한 경로의 한Q만 실행 중인지 확인한 뒤 같은 앱의 새 LaunchServices 보조 프로세스로 접근성(AX)·합성 키 전송(post) 허용을 조회한다. 기록에 저장한 버전·빌드 번호·코드 해시·실행 파일·plist가 바뀌면 새 준비가 필요하다. 목록 조회 도중 종료된 일회성 프로세스는 실제 소멸을 확인한 뒤 제외한다. 살아 있는 프로세스의 조회 실패에는 중단하며 본체 유일성·시작 시각·권한 확인 기준은 유지한다. AX와 post가 모두 true일 때만 종료 코드 0과 `permissions_ready`를 기록한다. 권한 미허용은 종료 코드 2, 앱 변경·검사 오류는 종료 코드 1이며 실제 앱·입력 테스트를 시작하지 않는다. 권한 조회 통과는 입력 감시 활성화나 실제 키 동작 검증을 대신하지 않는다.

테스트 기록에는 앱의 전체 경로·버전·빌드 번호, 단계별 완료·대기·오류와 새 프로세스의 권한 조회 결과를 남긴다. 기존 목록의 한Q가 ON인 사실만으로 새 빌드의 준비가 끝났다고 판단하지 않는다. 직접 확인·조작할 수 없는 GUI 단계만 사용자에게 요청하고 완료를 추정하지 않는다. 승인·검사 완료 후 앱의 입력 감시와 실제 입력 동작을 별도로 확인한다. 독립 자동 검사는 승인 대기 중에도 계속 수행할 수 있다.

`python3 Tests/AppTestPreparation/test_prepare_app_test.py`는 실제 앱 종료·권한 변경 없이 준비 순서, 종료·초기화 실패 시 중단, 다른 번들의 제외, 앱 변경·프로세스 변경·권한 거부·검사 오류 처리와 기록 보존을 검사한다. 실제 `tccutil` 초기화·GUI 승인·입력 테스트와 구분한다.

동일 인증서·동일 설치 경로의 권한 재사용은 macOS 15.7.9의 로컬 빌드 교체와 Sparkle 업데이트에서 확인했다. 공개 0.2.0의 ad-hoc 서명에서 0.3.0의 자체 서명으로 전환할 때는 손쉬운 사용 재승인이 필요할 수 있다. 다른 Mac·OS나 서명 구성에는 이 결과를 그대로 적용하지 않는다.

자체 서명은 Developer ID 서명·공증과 다르며, 다운로드한 앱의 최초 실행은 Gatekeeper에 차단될 수 있다. 실행 예외 승인과 손쉬운 사용 승인은 별개다. `prepare`의 프로세스 관측만으로 실행 차단이 해제됐다고 판단하지 않으며, 정상 실행과 `check`의 권한 검사를 모두 완료한다. 서명 방식의 구분은 [Apple 코드 서명 요구사항 안내](https://developer.apple.com/documentation/technotes/tn3127-inside-code-signing-requirements)를 참고한다.

### 검증된 동일 인증서의 권한 재사용

이전 prepare/check가 permissions_ready인 기록과 승인 당시 앱의 정확한 사본을 보존한다. 동일 설치 경로의 새 빌드에는 다음 명령을 사용한다.

```sh
python3 scripts/prepare-app-test.py prepare build/candidate/HanQ.app \
  --reuse-permissions-from <이전-record.json> \
  --previous-app <승인-당시-앱-사본>
```

도구는 이전 승인 기록·앱 사본의 해시·같은 경로·실제 인증서 지문·코드 식별 조건을 대조한다. 기존 한Q 종료 후 새 보조 프로세스에서 AX·post를 확인하고 둘 다 허용된 경우에만 새 본체를 실행한다. 실행 뒤에도 같은 앱의 새 보조 프로세스로 다시 검사한다. 권한 초기화와 GUI 재승인은 수행하지 않았다고 기록하며, 초기화 완료로 표시하지 않는다. 거부·조회 오류·다른 인증서·변경된 이전 사본이면 진행을 중단한다. 필요하면 일반 prepare와 GUI 승인으로 복구한다. 기존 승인 기록만으로 새 앱을 통과시키지 않으며 실제 키 입력 검증은 별도다.

### 별도 후보 빌드와 업데이트 의존성

`bash scripts/build-app.sh --candidate`는 `build/candidate/HanQ.app`을 생성한다. 기존 `build/HanQ.app`은 계속 실행할 수 있으며 후보 앱 자체가 실행 중이면 교체하지 않는다. 실제 입력 검증은 기존 앱을 종료한 뒤 같은 설치 경로에서 수행하며, 위 권한 사전 체크를 완료한다. 후보 생성과 실제 실행 검증은 구분한다.

Sparkle 2.10.0 공식 아카이브와 SHA-256은 `scripts/prepare-sparkle.sh`에 고정한다. 최초 빌드에는 네트워크가 필요하고 이후 검증된 로컬 아카이브를 사용한다. 프레임워크의 심볼릭 링크·서명과 라이선스를 보존해 앱에 포함한다. 공개 업데이트 주소·검증키는 `updates/config.json`에 있으며 개인키는 포함하지 않는다.

`bash scripts/test-update-policy.sh`는 정책 서명·경계·만료·적용 범위와 네트워크 실패·정책 철회의 기능 복귀 결정을 검사한다. `test-lifecycle.sh`는 제한 시 입력 해제·재활성화 방지·설정 보존도 확인한다. 실서버 조회는 `bash scripts/test-update-network.sh`로 별도 확인한다. `bash scripts/test-update-integration.sh`는 별도 번들에서 실제 안내창·AppDelegate 제한·오프라인 복귀·서명된 정책 철회를 함께 검사한다. `--interactive`는 재확인 버튼을 직접 확인할 때 사용한다. 운영 정책·실제 한Q 설정·전역 입력 탭은 변경하지 않는다.

실제 Sparkle 설치 검증용 별도 앱은 `Tests/UpdateEndToEnd/`와 `scripts/prepare-update-e2e.sh`에 있다. 새 임시 폴더를 만들고 같은 경로를 서버와 준비 스크립트에 전달한다. 서버가 실행된 뒤 다른 터미널에서 준비 스크립트를 실행한다.

```sh
# 첫 번째 터미널
trial=$(mktemp -d /private/tmp/hanq-update-e2e.XXXXXX)
mkdir -p "$trial/server"
printf '시험 폴더: %s\n' "$trial"
python3 Tests/UpdateEndToEnd/server.py "$trial"

# 두 번째 터미널: 위에 출력된 시험 폴더의 절대 경로 사용
HANQ_UPDATE_E2E_ROOT=<시험-폴더> bash scripts/prepare-update-e2e.sh
```

기본 경로는 `/private/tmp/hanq-update-e2e-$UID`이며, 위처럼 새 경로를 명시하면 실행별로 격리할 수 있다. Documents 아래의 이전 시험 폴더는 재사용하지 않는다. 서버는 127.0.0.1에만 바인딩한다. `installed/HanQ Update E2E.app`에서 테스트 업데이트를 실행해 설치·재실행 후 `result.json`의 빌드 2·설정 유지·동일 경로를 확인한다. 잘못된 서명과 취소 경로도 확인한다. 테스트 전용 HTTP 허용·번들 ID·임시 키는 해당 테스트 앱에만 포함된다. 종료 후 앱·서버를 닫고 `test-signing.key`를 삭제한다. 재실행할 때는 이전 테스트 디렉터리를 옮겨 새 환경을 만든다.

필수 정책과 설치를 연결하는 검증도 `/private/tmp` 아래에 새 시험 폴더와 `server` 하위 폴더를 만들고 같은 서버 스크립트에 전달한다. 같은 경로를 `HANQ_UPDATE_E2E_ROOT`로 지정해 `bash scripts/prepare-update-e2e.sh --required`로 준비한다. 경로를 생략하면 `/private/tmp/hanq-update-required-e2e-$UID`를 사용한다. 별도 번들 `taek.in.hanq.required-tests`에서 동일하게 서명된 최소 빌드 2 정책을 유지하며 빌드 1의 제한 안내 → Sparkle 설치·재실행 → 빌드 2의 제한 해제를 확인한다. `result.json`의 `policyChecked`, `restricted`, 빌드·설정 유지 값을 검사한다. 정책 GET과 다운로드 가능 여부 HEAD는 테스트 응답이며, 실제 운영 HTTPS 정책 조회나 키 입력 중단·복귀를 대신하지 않는다. 종료 후 해당 서버와 테스트 앱을 종료하고 임시 `test-signing.key`를 삭제한다.

이 검사는 한Q 배포본의 손쉬운 사용 권한 유지나 최초 다운로드 Gatekeeper 검증을 대신하지 않는다.

### 수동 테스트 창을 포함한 개발 빌드

일반 빌드는 수동 테스트 창을 포함하지 않는다. 개발용 검증이 필요하면 한Q를 종료한 뒤 `bash scripts/build-app.sh --development`로 빌드한다. 기존과 같은 `build/HanQ.app`을 백업·교체하므로 개발 빌드를 배포 파일로 사용하지 않는다.

`bash scripts/test-development-build.sh`로 앱 초기화 없이 일반·개발 모드의 테스트 액션 포함 여부를 실행 검증할 수 있다.

개발 빌드에서만 다음 실행 옵션을 사용할 수 있다. 새 개발 빌드의 권한 사전 체크를 먼저 완료하고, 앱이 이미 실행 중이면 종료한 뒤 실행한다.

```sh
open build/HanQ.app --args --test-jamo-panel
# 또는
open build/HanQ.app --args --test-hanja-panel
```

테스트 창은 Edge의 자모 변환과 TextEdit의 한자 처리를 수동으로 확인하는 도구다. 실제 우측 키 입력 검증을 대신하지 않는다. 창·버튼·지연 실행 코드는 `DevelopmentTestPanels.swift`에 있으며 `HANQ_DEVELOPMENT` 조건에서만 컴파일한다.

### 메뉴바 항목 복구 검증

`StatusItemController.swift`는 입력 감시와 독립적으로 메뉴바 항목을 유지한다. `bash scripts/test-status-item.sh`는 별도 AppKit 프로세스에서 실제 메뉴바 항목의 숨김·빈 이미지·0폭·메뉴 누락·등록 제거를 유발하고 복구를 검사한다. 화면 변경 알림의 중복 처리·복구 간격·열린 메뉴 대기·같은 메뉴·저장 식별자·AppKit 제거 전후 저장 위치 유지·연속 숨김의 반복 생성 방지·종료 후 예약 취소도 확인한다. 정상 상태에서의 명시적 재실행 복구·연속 요청의 기한 유지·3회 반복 안내와 유효 시간·별도 프로세스의 요청 전달·피드백 버튼 콜백도 검사한다. 안내는 `MenuBarRecoveryNotice.swift`의 비모달 창으로 입력 처리 루프를 중단하지 않는다. 전역 입력 탭·권한·한Q 사용자 설정은 사용하지 않으며 실제 앱·물리 키 검증과 구분한다.

실제 앱은 권한 사전 체크 후 외부 모니터 연결/해제·주 화면 변경·잠자기 복귀·메뉴를 연 상태의 화면 변경과 앱 다시 열기를 확인한다. 공간 부족·전체 화면·자동 숨김·메뉴바 관리 앱의 숨김·macOS 26 이상의 앱별 메뉴바 허용 OFF를 등록 오류와 구분한다. 시스템 허용 OFF를 자동으로 켜거나 다른 관리 앱의 설정을 변경하지 않는다. 진단 모드의 `status.state`는 항목·표시 플래그·버튼·이미지·창·화면 포함 여부·화면 개수를 기록하며 실제 픽셀 표시나 시스템 허용 상태의 확정값으로 해석하지 않는다. 재등록 사유는 시스템 로그에도 남긴다. 입력 문자열·키 값·화면 내용은 기록하지 않는다.

빌드 203의 메뉴바 동작은 macOS 15.7.9에서 권한 사전 체크를 마친 실제 앱으로 확인했다. 실행 중 다시 열기에 따른 재등록, 60초 안의 1·2회 요청에는 안내가 없고 3회째에 표시되는 동작, 안내 창의 피드백 버튼으로 브라우저에 폼을 여는 동작과 창 닫힘을 확인했다. 피드백은 제출하지 않았다. Ice를 종료한 상태의 재등록·화면 위치 유지는 창 상태로 확인했고, Ice 재실행 뒤 숨김 영역 안의 아이콘 표시는 사용자 육안 확인으로 구분한다.

등록 제거·빈 이미지 등 강제 누락의 복구는 자동 AppKit 검사에서 확인했으며, 실제 제품의 자연 발생 누락을 재현한 결과로 확대하지 않는다. macOS 26.6.2의 해당 증상, 외부 모니터 연결/해제, 물리 키 입력은 이번 메뉴바 확인 범위에 포함하지 않는다. 잠자기·깨우기 후 정상 동작은 별도의 사용자 확인 결과이며, 자연 발생 아이콘 누락의 재현·복구 검증과 구분한다.

### 외부 키보드 설정 검증

`bash scripts/test-external-keyboards.sh`는 임시 UserDefaults와 합성 이벤트로 기기 식별·설정 보존·두 키 등록·반복·놓음·기기 분리·다른 키보드 modifier 보존을 검사한다. `--inventory`는 실제 IORegistry에서 읽은 키보드 서비스 개수만 출력한다. `--ui`는 별도 테스트 프로세스에서 실제 설정 창을 열고 저장·취소·분리 경로를 확인하며 `.build/hanq/external-keyboard-setup.png`를 생성한다. 전역 이벤트 탭과 실제 한Q 설정은 사용하지 않는다.

화면 검사는 macOS의 키 상태 조회에 눌린 키가 없을 때만 시작한다. 최대 10초 동안 기다린 뒤에도 눌림이 보고되면 오류로 종료하며, 화면 검사·이미지 생성을 통과로 세지 않는다. 조회값만으로 사용자가 실제 키를 누르고 있다고 단정하지 않는다. 이미지가 남아 있어도 이전 실행의 산출물일 수 있으므로 현재 실행의 성공 여부를 함께 확인한다.

구현은 `ExternalKeyboardModel.swift`(식별·설정·키 상태), `ExternalKeyboardDevices.swift`(읽기 전용 기기 알림·비공개 이벤트 기기 필드), `ExternalKeyboardController.swift`(확인 흐름·기기별 처리), `ExternalKeyboardSetupView.swift`(확인 창 레이아웃)에 나뉜다. Quartz 비공개 필드 87의 값은 현재 키보드 서비스 목록과 정확히 일치할 때만 사용한다. 필드의 지속 지원이나 실제 키보드 입력과의 연결은 자동 검사로 보증하지 않는다.

실물에서는 USB/Bluetooth 최초 연결·기연결 시작·다시 연결·앱 재시작·내장/외장 번갈아 입력·포커스 변경·물리 한영/한자키·동일 모델 두 대·외부 매핑 앱·잠자기·보안 입력을 확인한다. 일련번호가 없는 기기의 포트 변경과 연결 방식 변경은 새 기기 등록이 필요할 수 있다. 연결 위치마저 없는 기기는 재연결 시 다시 등록한다.

## 수정 시 주의할 점

### 권한과 프로세스 수명

권한 감시·watchdog·재실행을 수정할 때는 [권한과 프로세스 수명 명세](SPEC.md#권한과-프로세스-수명)를 기준으로 다음을 검증한다.

- 권한 없는 인스턴스와 검사·재실행용 보조 프로세스가 입력을 가로채지 않는지.
- 탭 해제 시 눌린 키 상태와 대기 작업이 정리되고 UI 중복 실행이 차단되는지.
- 확인된 권한 거부에만 한 번 재실행하며, 사용자 종료·검사 오류·시간 초과에는 재실행하거나 반복 재시작하지 않는지.

### 텍스트 편집

자판 배열 선택과 두벌식 대체 조건은 [선택 영타 변환 명세](SPEC.md#선택-영타-변환)를 따른다. OS 변경 시 세벌식·로마자 자판 자료 로딩과 실패 시 기본값 적용을 함께 확인한다.

자판 자료는 `KoreanKeyboardLayout`에서 읽고 로마자 조합 규칙은 `JamoComposer`에서 공유한다. 선택 영타 변환 검사는 기존 실제 IME 관측값 중 로마자 274개를 대조한다. 배열 처리를 변경할 때는 감지·변환·후속 조합과 실제 IME 결과를 각각 검증한다.

순수 변환 로직과 AX·붙여넣기 처리를 분리한다. 텍스트 범위는 AX와 동일하게 UTF-16 기준으로 처리하고, 명시적 선택은 커서 문단 범위보다 우선한다.

비동기 편집 전에는 권한·보안 입력·포커스·텍스트·선택·입력 변경 여부를 재확인한다. 클립보드 복원 시 사용자가 새로 복사한 내용을 덮어쓰지 않는다. 입력 내용은 로그에 기록하지 않는다.

편집기마다 AX 지원과 한자 후보 처리, Undo 동작이 다르다. 한자 원문 중복 보정은 정상 대체 결과를 다시 편집하지 않도록 제한한다. 기본 입력기의 변환과 보정 붙여넣기는 별도 편집이므로 Undo 한 번으로 원문까지 복원된다고 가정하지 않는다.

### 한자 후보 조회 검증

`HanjaCandidates.swift`는 Apple 기본·사용자 사전을 비공개 DictionaryServices IDX API로 조회한다. 조회는 실패·신호 종료·시간 초과를 격리하는 보조 프로세스에서 수행한다. 사전을 생성·수정하지 않고 조회 문자열을 명령행·로그·파일에 기록하지 않는다. 후보 목록은 프로세스 간 파이프로만 전달하며 원문과 동일한 항목과 중복을 제거한다. 64음절 초과 대상·128개 또는 JSON 4KiB를 넘는 결과·750ms 시간 초과에는 기존 호출로 복귀한다.

`HanjaCandidatePanel.swift`는 Apple InputMethodKit 후보창을 사용하며 입력 소스를 등록하거나 선택하지 않는다. 비공개 delegate와 후보 객체 접근은 실행 중 메서드·프로토콜 계약을 확인한 뒤 사용하고, 지원하지 않는 계약은 기존 Apple 입력기 호출로 복귀한다. `HanjaCandidateSelection.swift`는 후보 순서·9개 단위 페이지와 키 대응을 관리한다. 원문 선택은 확정 전까지 유지하고, 확정 시 JamoRepair가 대상 상태를 다시 확인한다. 이전 후보창의 콜백은 새 요청에 적용하지 않는다. OS 변경 시 표시·선택·마우스 확정과 실패 복귀를 별도로 확인한다.

`AXBoundsForRange`의 빈·잘못된 좌표를 거부하고 실제 입력칸 범위와 대조한다. Chromium의 contenteditable에서 직접 범위 좌표를 제공하지 않는 경우 `AXSelectedTextMarkerRange`·`AXBoundsForTextMarkerRange`를 사용하며 선택 문자열도 대조한다. 0너비 커서는 양수 줄 높이가 있는 경우에만 허용한다. 위치 조회 중 본문·선택을 바꾸지 않으며 조회 실패는 기존 후보창 호출로 복귀한다.

`bash scripts/test-hanja-candidates.sh`는 실제 기본 사전과 격리된 사용자 사전으로 목록·빈 결과·원문 제외·파일 보존·조회 실패를 검사한다. 별도 서명 시험 앱에서 제품의 Apple 후보창·delegate와 숫자·방향키·페이지·취소·키 놓음·마우스 전달·이전 콜백 차단을 검사하며 입력 소스 등록·전환이 없는지도 대조한다. OS에 키를 전송하지 않는다. 전체 빌드에 포함되며 설치 앱의 전역 입력 경로·물리 한자키 확인과 구분한다.

후보 확정은 AX 선택만으로 조합이 끝났다고 가정하지 않는다. 편집기에 오른쪽 방향키를 전달한 뒤 같은 본문·포커스·입력 소스와 안정된 커서를 확인하고 대상 범위를 선택한다. 후보창은 Apple 제공 목록의 실제 내용 크기에 맞춰 조정한다. TextEdit와 Chromium의 textarea·contenteditable에서 조합 직후 확정과 중복 입력을 별도로 확인한다.

### 비공개 API

Caps Lock 전환 설정의 비공개 HIToolbox API 호출은 `RomanSwitchController.swift`에 격리한다. [Roman Switch 명세](SPEC.md#roman-switch-직접-제어--현재-구현-계약)를 기준으로 새 macOS에서 ABI·심볼 로딩 실패·설정 후 실제 상태를 확인한다. 최초 실행에 사용자의 시스템 설정을 덮어쓰지 않는다.

## 원래 입력 대상 보존

InputDeliveryOrigin은 별도 HID 탭에서 원래 활성 앱 대상을 기록하고 주 입력 처리 전후에 앱 전환을 확인한다. 불일치 보정의 HID 언어 의도와 같은 식별자를 유지하며, 직접 전달된 원래 키의 이력은 한 번 소비한다. 불일치 게이트 재시작 뒤에는 원래 대상 관측을 앞단에 다시 설치한다. `bash scripts/test-input-delivery-origin.sh`는 실제 키 전송 없이 이벤트 시각 변경·대상 변경·중복 소비·패널·합성 표식·만료·수명 해제를 검사한다. 대상 PID 지정 필드만 바꾸는 것으로 실제 전달 대상을 고정했다고 가정하지 않는다. 실제 지연·앱 전환·기본 IME와 누름·놓음 수신 검사는 별도로 수행한다.

원래 앱으로 직접 전달한 누름은 기기·키·생산 프로세스별로 반복과 놓음의 수신 앱을 유지한다. HID 앞단에서 대응 놓음을 처리하여 뒤의 보정기·후보창이 다시 소비하지 않게 한다. 종료된 앱의 PID를 새 프로세스에 재사용하지 않으며, 놓음과 감시 종료 시 소유 이력을 정리한다. 백그라운드 앱에 보낸 반복 누름은 일반 keyDown으로 전달하고 횟수·순서를 보존한다.

KeyboardStateMirror는 소비한 키를 별도 표식의 새 상태 전용 이벤트로 대체하여 Quartz의 HID·세션 키 상태를 갱신한 뒤 annotated session 경계에서 폐기한다. 입력 대상에 같은 문자를 다시 전달하지 않으며 원래 modifier flags를 보존한다. 경계 시작에 실패하면 입력 소비를 시작하지 않고, 경계가 중단되면 전체 입력 감시를 중지한다. 종료 시 이미 처리 중인 상태 이벤트를 제한된 시간 동안 정리한다.

`bash scripts/test-keyboard-state-mirror.sh`는 전역 전송 없이 표식 소유·원래 flags·종료 및 시험 도구의 누름 목록을 검사한다. `bash scripts/test-keyboard-state-native.sh <새-결과-디렉터리>`는 별도 시험 창 두 개에서 고정된 L·Shift만 전송하여 HID/세션 소비, 원래 앱의 반복·놓음, SIGTERM·포커스 이동 중단을 검사한다. 두 전역 키 상태와 각 창의 수신을 함께 확인하며 사용자 입력은 기록하지 않는다. 시험 도구는 실제 전송한 누름만 역순으로 정리하고 활성 앱 조회 전에 run loop를 처리한다. 종료된 수신 앱에는 보내지 않는다. SIGKILL·프로세스 충돌·전송 권한 상실은 정상 정리 절차로 보장할 수 없다. 실제 물리 키·외부 기기 검증과 구분한다.

`bash scripts/test-keyboard-state-physical.sh <권한-record.json> <새-결과-디렉터리>`는 실행 중인 후보에서 사람이 L 단발·반복, 우측 Command의 양방향 전환, 우측 Option의 선택 영타 변환, 각 우측 키를 누른 채 L 입력을 확인하는 7단계 도구다. 전역 이벤트 탭·OS 키 합성·키 상태 초기화 없이 시험 창의 고정 키 수신과 Quartz 상태를 관측한다. 문자 키는 keyState, 우측 modifier는 SDK의 좌우 flags로 누름·놓음을 확인하고 최종 키 상태도 대조한다. 시험 창은 표준 편집 메뉴와 선택 범위를 준비하며 실제 변환 결과를 최대 3초 동안 기다린다.

세 번째 인자로 이전 결과를 주면 동일 후보에서 성공한 앞의 최대 4단계를 이어받고 실패·미실행 단계는 다시 검사한다. `--verify-editor`를 세 번째 인자로 주면 물리 입력 없이 로컬 AppKit 붙여넣기 단축키의 메뉴 유무·실제 대치를 비교하며 임시 클립보드와 입력 소스를 복원한다. 이 자체 검사는 물리 입력 통과로 세지 않는다. 실행 파일·IPC는 공통 임시 시험 폴더에 두고 결과는 터미널이 복사한다. 종료 시 입력 소스를 복원하며, 실물 외장 키보드·다른 앱의 확인과 구분한다.

## 첫 자음 조합 보정 개발

`OnsetRecoveryController.swift`가 대상 앱과 한Q 입력 수명을 연결하고, `OnsetRecoveryEngine.swift`와 `OnsetInputGate.swift`가 보정·입력 대기를 담당한다. 실험 도구의 입력 로그와 UI는 제품에 포함하지 않는다. `bash scripts/test-onset-recovery.sh`는 실제 키 전송 없이 제품 엔진의 선택 대체·선택 해제 지연·선택 재시도·입력 순서·실패 복원을 검사한다. AppKit 검사는 제한된 실행 샌드박스 밖에서 수행한다. 실제 검증 시 독립 OnsetRecoveryProbe를 먼저 종료하여 두 보정기가 겹치지 않게 한다.

`bash scripts/test-onset-native-layouts.sh`는 별도 NSTextView에서 실제 다섯 IME의 첫 자음 대체·보관 모음/종성 조합을 확인한다. 로마자의 Shift 쌍자음과 배열별 복합 모음도 검사한다. 본문 조회·선택 변경·게이트 통과는 시험 대역을 사용하고 키는 해당 시험 프로세스에만 전송한다. 시험 후 입력 소스 선택·활성 상태를 복원한다. 설치본 전역 AX·물리 키 검증을 대신하지 않는다. 첫 예약의 빈 만료·키 놓음 통과·재예약과 엔진으로 이동한 미전달 키의 보존은 게이트 및 초기 조회 실패 회귀 검사에서 구분한다.

`OnsetCompositionCommit.swift`는 단일 자음을 선택하기 전 원래 프로세스의 방향키 처리로 조합을 확정하고 본문·커서 반영을 기다린다. 확정용 방향키는 문자 재입력과 다른 식별자를 사용하며 문자 전달 확인으로 계산하지 않는다. 첫 자음 회귀의 `CompositionCommit` 검사는 지연·미반영·대상/본문/커서/소스 변경·권한/보안 실패와 원래 입력 보존을 검사한다. 이미 분리된 자음을 표현하는 대역은 조합 확정 완료를 명시하며, 실제 편집기의 확정 경로 검증과 구분한다.

`bash scripts/test-onset-active-app.sh <권한-record.json> <새-결과-디렉터리>`는 실행 중인 후보와 소유 NSTextView에서 정상 조합 및 AX 편집 가능 상태가 늦게 공개되는 조건을 대조한다. 실제 IME 조합은 유지하고 AX 역할만 첫 키까지 지연시키며, 다섯 배열의 정상·Shift·종성·복합 모음과 긴 문장, 보정용 방향키/대체 키를 제외한 원래 키 순서·주변 본문·UTF-16 커서를 확인한다. 긴 문장 조건은 조합 확정 경로의 실제 실행도 요구한다. 대상 PID·전경·보안 입력·전송 권한·상태 감시가 바뀌면 송신을 중단한다. 입력 소스 선택과 선택 가능한 키보드 소스의 활성 목록을 복원하며 실제 앱·물리 키 검증과 구분한다.

`OnsetLateSequenceDetector.swift`는 다섯 한국어 입력기의 배열별 통과 이력과 본문·커서의 정확 일치를 검사하고, `OnsetCommittedReplacement.swift`는 공백으로 확정된 입력만 원래 AX 요소에서 한 번 치환한다. 쓰기 미지원·실제 대상 변경·소스 변경·추가 입력 경합에서는 편집을 강행하지 않는다. 보정 전 미확인 입력의 통과, 전송별 확인 기한, 일시 조회 실패, 재개 상태·기준 갱신과 확인된 빈 전달의 비동기 완료를 각각 회귀 검사한다. 접두부 직후 비동기로 추가되는 100개 입력의 개수·순서 검사는 유지한다.

`bash scripts/test-onset-late-native-layouts.sh`는 별도 NSTextView에서 다섯 실제 IME의 정상 입력과 첫 자음만 확정한 분리 입력을 각각 27건 대조한다. 배열별 Shift·종성·복합 모음과 세벌식 숫자·문장부호 키, 기존 본문·UTF-16 커서·소스 유지·단일 치환을 확인한다. 본문 조회·선택·치환은 시험 대역이며 설치본의 전역 AX 경로와 물리 키 검증을 대신하지 않는다.

`bash scripts/test-onset-late-app.sh <권한-record.json> <새-결과-디렉터리>`는 권한 사전 체크를 마친 실행 중 후보 앱의 전역 HID·실제 AX·실제 IME 경로를 별도 시험 창에서 27건 확인한다. 첫 키 분리와 AX 공개 지연을 인위적으로 재현하므로 정상 타자 검사와 구분한다. `--physical-normal`을 세 번째 인자로 주면 인위적인 분리 없이 사람이 다섯 입력기에서 정상 단어를 두 개씩 입력한다. 세벌식의 `s`는 종성 ㄴ이므로 정상 `k → f → s → Space`는 `간`을 만들지만, 앞의 초성이 이미 분리된 시험에서는 `s`가 무시될 수 있다. `--physical`은 이 분리 조건의 수동 재현용이다.

시험 앱·전송기·제어 파일은 임시 폴더에 두고 터미널이 결과를 지정한 디렉터리로 복사한다. 시험 앱이 Documents 폴더를 읽기 위한 권한을 요청하지 않는다. 실행 인자 없이 시험 앱을 다시 열면 입력 소스를 바꾸지 않고 종료한다. 시험 후 입력 소스 선택·활성 상태를 복원하며 다른 앱에 키를 보내지 않는다. 합성 키·정상 물리 키·분리 재현 결과를 각각 기록하고 앱별 실사용 확인과 구분한다.

`OnsetSafetyDiagnostics.swift`의 진단은 고정 사유·숫자 상태만 출력한다. 재진입 게이트 진단은 명시적으로 켠 실행에서 최대 256개 프레임과 초과 개수를 관리하고, 파일 쓰기는 게이트 잠금 밖에서 한다. 진단 켜기·끄기의 입력 동작 동등성과 입력 내용·키 값 제외를 자동 검사한다.

## 입력 소스 불일치 복구 개발

`MismatchRecoveryController.swift`는 제품 수명·설정, `MismatchRecoveryEngine.swift`는 감지·선택 덮어쓰기·결과 확인, `MismatchTextReader.swift`와 `MismatchSnapshotWorker.swift`는 본문 좌표와 비동기 조회를, `MismatchIdleObservation.swift`는 입력 대기 중 비동기 관측과 늦은 응답 배제를 담당한다. 앱별 예외 목록은 두지 않는다. `MismatchSourceSwitch.swift`는 직접 소스 선택과 내부 변경 알림의 소유권을, `MismatchSourceInteraction.swift`와 `MismatchSwitchGate.swift`는 복구 중 사용자 전환·메뉴 대기를 처리한다. 시험 도구의 원문 로그·장치 감시는 제품에 포함하지 않는다.

`bash scripts/test-mismatch-recovery.sh`는 제품 소스로 회귀 모드와 제품 수명·진단 비밀값 제외 검사를 실행한다. 실제 키 전송은 테스트 대역을 사용한다. 통합 빌드는 이 검사와 기존 첫 자음·앱 수명 검사를 함께 수행한다. 이전에 설치한 독립 AutoRecoveryProbe가 있다면 실제 앱 시험 전에 종료한다. 제품 진단은 복구 상태만 기록하므로 실제 문자 대조에는 별도 시험 driver의 기대값·결과를 사용한다. `--disable-mismatch-recovery`로 해당 실행에서만 복구를 끄고 비교할 수 있다. 일반 실행에서는 저장된 켜기/끄기 설정을 사용하지 않으며, 이전 `mismatchRecoveryEnabled` 값은 시작 시 제거한다. 독립 자동 복구 실험 앱 실행 중에는 제품 감시를 시작하지 않는다.

`--test-fragmented-proof`는 정상 조합·분리 자모·영문 구간의 기존 완전 분할 판정을 작은 입력의 참조 모델과 대조한다. Shift·복합 모음/종성·주변 본문/선택 변경과 관측 키보다 늦게 반영된 정상 본문의 긴 입력을 포함한다. 자모 성분 대조는 불가능한 후보를 빠르게 거절하기 위한 조건이며, 성분이 같아도 기존 구간·본문·커서 전체 일치를 통과해야 한다. OS 키 전송·AX·입력 소스 변경 없는 검사이며 실제 설치 앱의 중첩 입력·최종 수신 검사를 대신하지 않는다.

`MismatchKeyboardLayout.swift`는 Apple 한국어 다섯 배열의 물리 키 대응과 복구 결과 조합을 담당한다. `Tests/MismatchRecovery/NativeLayoutExpectations.json`에는 실제 IME에서 관측한 결과 중 중복을 제외한 349개 사례를 보존한다. 모든 키 조합을 검증한 자료는 아니다. 배열 검사에서는 이 결과와 소스 ID 유지·숫자 자모·정상 영문 제외를 확인한다. 공유 조합기의 기존 기본 동작은 유지한다.

`bash scripts/test-mismatch-native-layouts.sh`는 별도 AppKit 입력창에서 실제 다섯 IME와 제품 복구 엔진을 연결한다. 각 배열의 영문·혼합 접두부와 두벌식 전체 혼합 단어 복구를 포함한 11개 사례를 검사한다. 원래 키와 대기 중인 모음·종성의 최종 문자·커서·전송 횟수·잔여 키·소스 ID를 확인한다. 본문 조회와 선택 쓰기에는 테스트 대역을 쓰고, 소스 선택에는 제품의 직접 API 경로를 사용한다. `--source-interactions`는 Caps 설정 ON/OFF·메뉴 영어/다른 한국어 전환 20건, `--source-interactions-single`은 단일 자음 뒤 영어 입력 10건, `--source-interactions-idle`은 후속 키 없는 최종 영어 전환 10건을 확인한다. 이 모드의 Caps·메뉴 소스 변경은 시험 코드로 재현하므로 실제 물리 키·메뉴 조작과 구분한다. `--legacy-source-switch`는 보존한 이전 Control-Space 구현과 같은 조건을 비교하는 시험 전용 경로다. `--activation-lag`는 소스 ID 반영 뒤 80ms 동안 시험창에 영문을 전달하여 준비 지연 시 재시도의 본문·커서·키 쌍·후속 입력 보존을 11건 검사한다. `--activation-lag-long`은 150ms 지연으로 두 번째 재시도까지 확인한다. 입력 내용 주입은 시험 대역이며 실제 macOS 지연의 측정값으로 해석하지 않는다. `--cycle-coalescing`은 영어 단계가 80ms 미만이면 시험 입력 문맥이 재활성화되지 않는 조건으로 두 단계 대기를 11건 확인한다. 이 조건도 macOS 내부 원인을 확정하는 측정이 아닌 시험 대역이다. 시험마다 새 입력창을 사용해 이전 IME 조합이 다음 사례로 넘어가지 않게 한다.

불일치 복구 중 이미 편집기에 전달한 키의 놓음은 즉시 통과시키고, 새로 보관한 키의 누름·놓음은 함께 전달한다. 복구용 소스 선택은 modifier·스페이스 이벤트를 합성하지 않는다. 내부 선택의 예상 소스와 실제 변경을 대조하여 사용자 전환과 구분한다. 주 입력 처리도 복구 중 전환 의도를 처리하여 보조 전환 감시가 우회된 경우 임시 영어 소스를 기준으로 반대로 전환하지 않는다. 관련 회귀 검사는 키 놓음 10건, 실제 Quartz 상태 ID 6건 및 앱 수명 검사의 주 전환 경로를 포함한다.

복구 중 Command-A는 보정이 본문·커서를 검증할 때까지 후속 입력과 함께 보관한다. 보정 완료 후 검증한 입력칸과 이력을 SourceSwitchBarrier에 넘기고 전체 선택·삭제·한영 전환·대체 입력을 도착 순서대로 처리한다. 실제 본문과 선택을 확인하기 전에는 후속 편집 키를 전달하지 않는다. 검증되지 않은 본문이나 바뀐 입력칸에는 선택·재전송하지 않는다.

### 마지막 재입력 재시도 검사

복구 회귀 검사는 30개 모드와 제품 수명·진단 비밀값 제외 검사로 구성한다.

`--test-monitor-lifecycle`은 유휴 탭 중단의 새 등록과 재등록 빈도 제한, 복구·보관 입력·전환 키·권한 거부·명시적 종료 시 재등록 중단을 검사한다. 대역을 사용하므로 실제 OS 탭 등록 검증은 별도로 수행한다.

`--test-activation-shortcut`은 마지막 재시도의 소스 소유권과 기존 기한·횟수, 미설정·사용자 지정 단축키·권한·modifier·포커스 조건에서의 중단과 합성 키 해제를 검사한다. 두벌식 소스 ID가 맞아도 실제 자판이 ABC이고 입력기 override가 없으면 단순 대기·재입력·직접 소스 재선택으로 복구되지 않을 수 있다. 마지막 재시도에서 이 상태를 확인하고, 활성화된 이전 입력 소스 선택이 Control-Space로 명확히 설정된 경우에만 OS 선택 경로를 사용한다. 설정을 변경하거나 창을 전환하지 않으며, 다른 단축키 설정에서는 기존 직접 API·HID 경로를 유지한다. 새 대조 시험에서 확인한 원인을 과거 브라우저 재현의 원인으로 확대하지 않는다.

마지막 사전 검사 뒤 실제 키 처리가 지연되는 동안 활성화가 풀리는 경우도 검사한다. 마지막 HID 결과가 정확한 영문 재현 또는 관측 키 전체로 증명한 분리 자모·부분 조합이고 원래 입력칸·본문·선택·두벌식 소스가 다시 검증되면, 아직 쓰지 않은 OS 재활성화를 한 번 적용하고 같은 구간을 재입력한다. 호출 프로세스의 정상 레이아웃 조회만으로 이 결과 검증을 생략하지 않는다. 직접 API 재시도 두 번과 별도로 이 추가 재입력은 한 번이며, 2.5초 진행 기한을 늘리지 않는다. 회귀 검사는 늦은 실패 뒤 복구·후속 조합, 재활성화 뒤 재실패의 종료, 본문·소스 변경·미설정·기한 부족·이미 사용한 대안의 중단을 포함한다. 일반 실행 로그의 재활성화 `stage=1`은 사전 상태 검사, `stage=2`는 실제 영문·분리 자모·부분 조합 실패 결과 검증 뒤의 경로다.

설치된 앱의 마지막 재시도는 `bash scripts/prepare-mismatch-paced-live.sh <권한-record.json>`으로 준비한 소유 시험 창에서 확인한다. 도구는 한Q·입력기를 종료하거나 입력 소스를 초기화하지 않는다. 도구가 소유 시험 창을 실행한다. 출력된 시험 루트의 `probe <시험-PID>`로 고정 RKS를 입력한 뒤 `probe <시험-PID> --continue`로 후속 모음을 검사한다. 결과 파일의 정상 조합·커서·재입력 횟수·원래 입력 소스를 대조한다. 준비 명령의 두 번째 인자 `--cold`는 초기 입력 문맥 조회를 제외하며, 실제 자판·override와 설치 앱의 재활성화 이벤트 출처도 기록한다. 합성 키 검사와 물리 키 확인은 구분한다. 강제 실패 창은 첫 키의 정상 처리 경로를 우회하기 전에 `NSTextInputContext`를 준비한다. 준비 여부에 따라 강제 실패 시험의 결과가 달라질 수 있으므로 이 조건을 기록한다. 이 대조 결과만으로 실제 편집기의 실패 원인을 확정하지 않는다.

`--test-composition-continuation`은 정상 글자 확인 뒤 조합이 끊겨 후속 모음이 `간ㅏ` 또는 `간k`로 남는 경로를 검사한다. 복구 완료 이력 인계·전체 키 재조합·앞선 영어 구간 보존·다음 자음 조합과 기존 문서·정상 입력·선택·탐색·입력칸·소스·기한·키 수 변경 시 인계 제외를 확인한다. 편집기·소스·키 전송은 대역을 사용하며, 설치 앱의 실제 배경 전환 뒤 후속 키 감지·복구와 구분한다. 일반 실행의 후속 조합 로그는 고정 문구만 기록한다.

마지막 HID 누름·놓음 전송 직후 소스 왕복도 결과 확인으로 이어지는지 검사한다. 키가 남은 상태의 소스 변경은 계속 중단하며, 전송이 끝난 경우에도 외부 전환 안정·본문·커서·기한 검증을 유지한다.

재입력 결과 검사는 전체 영문 실패 외에도 관측한 키 전체의 연속 구간별 영문·정상 한글·분리 자모 출력이 섞인 형태를 공통 검사로 대조한다. 각 구간과 전체 삽입이 정확히 일치해야 하고, 정상 결과·다른 키·주변 본문·선택·배열·64개 키 초과는 거부한다. 직전 교체 문자열과 다른 부분 결과의 남은 직접 재시도·후속 모음 조합 및 재시도 소진 후 미사용 재활성화 한 번과 사용 완료·기한·설정 불가 시 추가 전송 거부를 확인한다.

전달 순서 감시 검사는 현재 이력이 실제 정상 본문·관측 키 전체의 불일치·커서와 일치할 때만 인계되는지 확인한다. 직전 이력은 새 키 전달 전 검사에만 허용하며, 유휴 시 지연된 키의 생략과 원래 후보 기한의 연장을 거부한다. 복구 완료 이력의 인계 시각과 외부 소스 경계 시각은 이벤트 시각이 0이면 시스템 단조 시각을 사용하며, 양수 시각과 실제 인계 가능 여부를 함께 검사한다. 첫 자음 감시로 직접 이력을 놓친 경우의 후속 모음·자음 복구와 변경된 본문·선택·입력칸·소스·기한·명시적 전환 경계·키 수 초과·외부 편집 중 인계 거부를 구분한다.

`--test-source-settlement`은 외부 영어→두벌식 왕복 사이에 내부 소스 복원이 끼는 경합을 검사한다. 마지막 외부 소스와 키 시각 경계, 지속된 영어 선택, 명시적 전환 우선, 대기 중 키 보관, 300ms 제한·기한·포커스·취소와 오래된 타이머 무효화를 확인한다. 실제 소스 선택과 키 전송은 대역을 사용하며 설치 앱의 실제 배경 전환·후속 한글 조합 검증과 구분한다. 일반 실행의 외부 전환 대기 로그에는 단계·변화 횟수·한국어 여부만 기록한다.

`--test-buffered-jamo`는 첫 자음 검증 뒤 후속 키가 분리 자모로 남는 경로를 검사한다. 전체 키 구간 재조합·앞선 영어 구간 보존·후속 모음 연결과 입력칸·주변 본문·선택·소스·키 수·재시도·기한 변경 시 편집 중단을 확인한다. 소스와 키 전송은 대역을 사용하므로 실제 배경 소스 전환으로 재현한 설치 앱의 자동 복구와 구분한다. 일반 실행의 후속 자모 확인 로그에는 재시도 수만 기록한다.

`--test-paced-replay`는 세션 전송이 계속 실패하는 편집기 대역에서 마지막 HID 재입력의 조합 결과를 검사한다. Apple 한국어 다섯 배열·Shift·대기 중 모음 연결·키 누름과 놓음·취소·포커스·소스·기한 변경 시 중단을 확인한다. 키 전송·소스 선택·본문은 대역을 사용하며 실제 앱이나 물리 키 검증을 대신하지 않는다. 진단에는 마지막 HID 재입력의 시작·종료와 고정 중단 사유만 기록한다. 일반 실행에서도 고정 중단 코드·재시도 수를 시스템 로그에 남기므로 재현 상태를 바꾸거나 진단 모드로 다시 실행하지 않고 실패 상태를 확인할 수 있다. 입력 내용·키 값·앱 식별자는 기록하지 않는다.

### 물리 전환 검사와 시험 도구

`bash scripts/prepare-mismatch-source-live.sh <권한-record.json> <새-결과-디렉터리> <한Q-진단-log>`는 실제 한Q·HID·AX를 사용하는 물리 Caps Lock 시험 창을 준비한다. 권한 확인을 마친 동일 앱을 종료한 뒤 같은 경로에서 `--diagnose-input <로그>` 옵션으로 다시 실행하고 `check`를 통과해야 한다. 진단 로그와 시험 실행 파일·제어 자료는 `/private/tmp`에 둔다. 첫 키를 의도적으로 영문으로 삽입하고 본문 조회를 잠시 늦춰 복구 중 전환을 재현하므로 정상 타자 검사와 구분한다. 창 활성화·AX 포커스를 기다리며, 비활성 한국어 소스는 시험 동안 활성화한 뒤 종료 때 원래 선택·활성 상태·Caps 설정을 복원한다.

화면의 영문 키 위치대로 첫 키 → Caps Lock 직접 한 번 → 영문 글자 키 두 개(예: A, B)를 입력한다. 글자 두 개는 실제 물리 키로 기대값을 계산하므로 AN·BC도 같은 전환 검증으로 인정한다. 삭제·추가 키·단축키·직접 본문 수정은 통과시키지 않는다. `bash scripts/test-mismatch-source-rules.sh`로 유효한 글자·잘못된 첫 키·삭제·추가·알 수 없는 키의 57조건을 OS 키 전송 없이 검사한다. 복구 중 보이는 임시 소스 변경을 사용자의 Caps 입력으로 대신하지 않는다. 본문·커서·소스·한Q의 실제 전환과 복구 완료를 함께 확인하고, 본문이 같아도 추가 입력·직접 수정·복구 미완료는 통과로 세지 않는다. 입력 도중이나 실패 판정 뒤에도 같은 단계 다시 시도 버튼을 사용할 수 있다. 감시가 정상인 경우 같은 창에서 바로 초기화하고, 중단된 경우 터미널에서 실행한 시험 전용 helper가 정확한 앱·소유 시험창·현재 단계·새 권한을 확인해 한Q만 자동 재준비한다. 시험창·단계·이전 실패 기록은 유지하며 다른 앱으로 초점이 옮겨졌거나 앱 내용·권한이 달라지면 진행하지 않는다. 종료하면 helper도 정리된다. 재시도에 따른 임시 입력 폐기는 소유한 시험 입력에 한정한다. 결과는 시험 종료 전에 터미널로 복사한다. 성공한 이전 결과를 네 번째 인자로 주면 해당 입력기부터 이어간다. 첫 키 전에는 정확한 한Q 프로세스의 최신 진단 pulse로 감시·권한·두 탭 활성과 유휴 상태를 확인한다. 감시 중단·오래된 진단·다른 프로세스이면 가짜 영문을 삽입하지 않고 입력을 잠근다. `--self-check-monitor`는 이 조건에서 첫 키가 본문을 바꾸지 않는지 자체 검사한다. 각 결과에 권한 기록의 한Q 빌드 번호를 남기며, 다른 빌드의 이전 성공을 최신 빌드 통과로 바꾸지 않는다. 다섯 번째 인자의 `--single`은 두벌식 한 단계 재확인용이다. 네 번째 인자를 빈 문자열로 두고 다섯 번째에 `--menu-suite`를 주면 입력 메뉴의 영어 선택·다른 한국어 선택·취소를 검사한다. `--smoke-five`는 소유 창의 첫 키 한 쌍을 별도 `Live/probe.swift` 전송기로 보내 실제 AX·복구 완료를 대조하는 자동 진단용이며 물리 Caps·메뉴 통과로 세지 않는다.

실제 메뉴 검사는 `prepare-mismatch-source-live.sh`의 다섯 번째 인자에 `--menu-single-suite`를 주어 첫 키 하나 뒤 영어 선택·세벌식390 선택·취소를 확인할 수 있다. 화면 맨 위 메뉴바 오른쪽의 현재 입력 소스 아이콘을 클릭해 두벌식·ABC 등의 목록을 연다. 한Q 상태 메뉴와 구분한다. 포인터를 입력 소스 아이콘 위에 미리 두고 첫 R 위치 입력 직후 메뉴를 열며, 선택·취소 뒤 화면의 후속 키를 입력한다. `--menu-suite`는 기존 세 키 접두부를 쓰는 대조 모드로 유지한다. 두 모드 모두 실제 메뉴 중단·재개, 최종 소스·본문·커서·복구 완료를 확인하며, 메뉴를 열기 전에 끝난 복구를 메뉴 처리 통과로 세지 않는다. 첫 키를 의도적으로 영문으로 넣는 조건이므로 시험창에서 첫 R이 보이는 것과 한Q의 정상 입력 동작을 구분한다.

`--diagnostic-three`는 소유 창의 고정 RKS 자동 대조용, `--physical-three`는 사용자가 직접 RKS를 입력하는 감지 진단용이다. 메뉴·Caps 전환 없이 두벌식의 본문·커서·소스와 복구 완료를 확인하며, 물리 입력 여부는 사용자 확인과 함께 기록한다. 이 진단의 성공을 실제 메뉴 검사 성공으로 대신하지 않는다.

물리 Caps 검사에서 후속 글자가 대문자로 나올 때에는 실제 키 이벤트의 Caps Lock 상태로 기대값을 계산한다. `test-mismatch-native-layouts.sh --english-case`는 다섯 입력기 복구 뒤 영어 키의 Caps Lock·Shift 네 조합을 실제 IME로 20건 검사한다. Caps 제스처와 AX는 시험 대역이며 물리 검사와 구분한다. 재시도 helper는 별도 세션으로 실행해 준비 명령이 끝난 뒤에도 유지한다. `prepare-mismatch-source-live.sh`의 `--self-check-retry-reprepare`는 준비 종료 3초 뒤 미준비 상태를 재현하여 같은 창·단계·기록을 유지한 자동 한Q 재실행과 새 권한 확인을 검사한다.

시험 도구는 단계 시작 시 진단 파일의 끝 위치를 기록하고 새 바이트만 최대 64KiB씩 읽는다. 필요한 복구 기록만 최대 1MiB 보관하며 기록 유실·잘림·한도 초과는 통과로 처리하지 않는다. 장시간 대기 중에도 재시도 helper는 소유 시험창이 살아 있는 동안 유지되며 종료·충돌·강제 종료 뒤 정리된다. 재준비 응답이 15초 안에 없으면 같은 단계 재시도 버튼을 다시 활성화한다.

### 입력 보정 변경의 필수 회귀 확인

`bash scripts/test-deletion-composition.sh`는 실제 제품의 전달 이력과 불일치 감지 엔진을 연결해 삭제 뒤 정상 조합을 검사한다. 전체 본문·커서로 증명된 확정 경계 뒤 새 초성을 이전 단어 전체의 복구로 승격하지 않는지, 살아 있는 연속 조합과 영문·분리 자모·모음 단독 후속 오류의 복구는 유지하는지 확인한다. 반복 삭제, 첫 한영 전환과 소스 왕복, 입력칸·선택·기한 및 웹 공백 표현 보존도 검사한다. 키·소스 선택·AX 쓰기는 대역이며 전역 입력을 보내지 않는다. 일반 `test-source-switch-barrier.sh`와 앱 빌드 검사에도 포함된다.

실제 앱 확인은 새 빌드의 권한 사전 체크를 마친 뒤 다음 순서로 수행한다. 처음부터 입력창을 클릭하는 준비 동작으로 최초 진입 상태를 없애지 않는다.

- 한자 선택 후 우측 Option 후보 표시·취소, 일반 Command 단축키, 한영·한자 기능 설정에 따른 키 통과를 확인한다.

앱별 결과와 실행 빌드를 기록하고, 검사하지 못한 조합은 미확인으로 남긴다. 실패 시 한Q를 끈 비교도 수행하되 앱 자체 동작이라는 결론은 같은 조건의 결과로 판단한다.

## 검증과 진단

### 간헐적 입력 이상 기록

전환 시점 조사에는 선택적 `eventEvidence`·`caretPrecedingClass`와 `kind=12` HUD 단서를 사용한다. `eventEvidence`는 기존 HID/메인 event·제어 frame에 원래 OS `timestampMicros`(0은 미측정), trace 시작에 대한 `observedAtMicros`, 물리 키의 고정 분류 `keyClass`만 추가한다. 분류는1공백/2문자키 위치/3편집·탐색/4modifier/5pointer/6기타이며 실제 글자·키 코드·Unicode payload·원래 flags를 저장하지 않는다. 캡처의 `clockOriginMicros`와 관측 시각을 합쳐 OS 이벤트부터 관측까지의 경과를 계산한다. 서로 다른 단계에서 OS 시각이 재설정될 수 있고 익명 이벤트 연결은 계속 보조 정보이므로, 시각0·구형 필드 없음·미연결을 추정하지 않는다. 마이크로초 정수 변환에는 약1µs 반올림 차이가 있을 수 있다.

기존 본문 snapshot의 변경 또는 커서 이동 때 커서 바로 앞 UTF-16 한 단위만 분류하고 `shapeEvidence.caretPrecedingClass`에0미확인·앞 글자 없음·선택 중/1ASCII 영문/2한글 음절/3자모/4공백·탭·줄바꿈/5기타를 남긴다. 좌표·원문은 진단 큐로 넘기지 않으며 입력칸 추가 조회·타이머·전환·키 전송은 없다. 이 값은 같은 AX 제공자의 관측이고 어떤 물리 키의 결과인지 또는 실제 IME 내부 상태인지 독립적으로 증명하지 않는다.

불일치 감지에서는 영어 소스 판단, 전환 이전 키, 다른 편집·외부 키 등록·첫 자음 복구/예약에 따른 보류, 조회 실패, 후보 생성·거절·만료·본문 불일치와 복구 시작 거절을 고정 사유로 구분한다. 전달 이력 인계는 전환/편집 진행·선택·입력칸·소스·시각 경계·미초기화 시각·이력 없음·기한·본문 불일치·허용을 구분한다. 분기 판단 자체에는 이미 사용한 고정 상태만 기록하며 입력 소스 ID는 저장하지 않는다. 원본 키 시각은 위의 선택적 eventEvidence에서 별도로 구분한다. 개별 키의 사유는 기존 익명 이벤트 번호에 연결하고, 유휴·적격성·인계 판단은 같은 사유가 이어지는 동안 중복을 생략한다. 파일 형식1에 `kind=8`을 추가하며 `edge`는 판단 위치, `category`는 고정 사유 코드다. 요약기의 `detection_decision_counts`와 `correlated_detection_decisions`에서 사유와 이벤트 연결을 확인한다. 예전 기록에 없던 사유를 추정해 채우지 않는다. 분기 사유는 입력 callback에서 진단 잠금을 기다리지 않고 별도 직렬 큐에 넘긴다. 최대4,096개 대기 슬롯 중3,072개는 개별 입력과 비정상 판단,1,024개는 입력에 연결되지 않은 영어 판단·관측 허용·후보 없음에 사용한다. 잠금이 풀리면 원래 관측 시각·익명 이벤트 연결을 보존해 기록하고, 캡처 요청 이전에 큐에 들어온 판단을 먼저 반영한다. 이벤트 객체나 키 값·문자열을 대기열에 보관하지 않는다. 유휴 중복 억제는 이 큐에서 입력된 순서로 수행하며 일시적인 상태 변경도 남긴다. 분기 frame의 `sequence`는 반영 순서이고 `milliseconds`는 원래 관측 시각이므로 두 순서를 혼동하지 않는다. 대기 슬롯이 찬 경우에만 별도 상한 초과 계수에 판단 위치·사유·개별 이벤트 연결 여부를 남긴다. `decisionDelivery.capacity`와 `decisionDelivery.overflow`는 선택적 메타데이터이며 구형 파일도 읽을 수 있다. 넘침 코드는 `((site-1)*31+(reason-1))*2+eventBound`로0–309 범위다. 요약기의 `decision_queue_capacity`·`decision_queue_overflow`로 해석한다. 넘침 계수는 쓰기 큐에서 제한된 묶음으로 반영하므로 지연될 수 있다. 분기 frame의 선택적 `decisionTiming`은 `queueMicros`(제출→worker 시작), `contended`(worker의 최초 try-lock 실패), `lockWaitMicros`(실패 후 잠금 획득 호출 전→획득 직후), `clipped`를 기록한다. 입력 callback이 잠금을 기다린 시간이 아니며, 획득 경과에는 OS 스케줄링 지연도 포함된다. 경합해도 마이크로초 해상도 미만의 짧은 획득은0으로 보일 수 있다. 시간은 단조 시계에서 측정하고 마이크로초 미만을 버리며60초 상한을 넘으면 잘림을 표시한다. 같은 유휴 사유도 실제 경합이면 frame을 남긴다. `decisionDelivery.waits`는 기존0–309코드별 처리 호출 수·경합 건수·잠금 대기 합계/최대·큐 대기 최대·잘림 건수를 누적한다. 경합하지 않은 중복 억제 호출도 이 집계에는 포함하며 합계는 상한 적용 후 값이다. 여러 파일의 누적값을 더하지 않고 같은 실행의 최신 집계를 사용한다. 요약기의 `decision_lock_waits`는 현재 파일에 남은 개별 경합, `decision_wait_totals`는 실행 중 누적 집계다. 오래된 파일의 해당 필드 없음은 미측정으로 처리하고0으로 추정하지 않는다. 제한된 최근 기록·용량 한도는 유지하며 무손실 전체 기록을 보장하지 않는다. 별도 기록/자동 입력 도구를 쓰는 경우 새 형식을 지원하도록 도구도 다시 빌드한다.

핵심 이벤트의 전달·소비·처리 시간, AX 조회 시작/끝, 본문 길이/선택 변화, 복구·보관 상태, 전환 경계와 수동 표시는 같은 직렬 worker에서 원래 관측 시각을 유지해 기록한다. 입력 callback은 진단 잠금을 얻지 않으며, 이벤트 객체 대신 호출 시점의 숫자 참조·분류만 넘긴다. 일반 관측은 기본4,096자리 중 이벤트2,048·핵심 상태1,536·반복 shape/timer512로 나누어 예약한다. 별도 AX 조회128자리에서 시작과 종료 두 작업을 함께 예약하며, 조회가 끝나면 자리를 반환한다. 분기의 기존4,096자리 예약은 유지한다. 대기열이 차면 호출자를 기다리게 하지 않고 종류별 초과를 집계한다. 지연 callback·AX 종료 및 전환 실패·수동 저장의 캡처 요청은 관측 자리 초과와 독립이며, 같은 trigger의 진행 중 요청은 하나로 묶는다.

소스 확인 진단은 kind10·mismatch lane4의 `sourceEvidence`다. edge1–7은 확인/요청/선택 확인/임시 보존/복귀/무효화/일반 영문 생략이다. `selected`·`confirmed`·`target`은0=미확인,1–5=기존 한국어 배열 순서,6=영문 keylayout,7=다른 소스다. `observedAtMilliseconds`·`confirmedAtMilliseconds`·`targetAtMilliseconds`는 단조 uptime 밀리초이고 선택 확인 전에는 해당 확인값이 없을 수 있다. `targetEventMilliseconds`는 원래 전환 키 경계의 단조 시각이다. `confirmedAgeMicros`·`targetAgeMicros`는 확인/요청 후 경과 시간이며60초를 넘으면 `ageClipped`가 true다. `committed`·`deferred`·`candidatePreserved`·`historyPreserved`로 선택 확인·보존 상태를 구분한다. 입력 소스 ID·표시 이름·문자·키 값은 저장하지 않는다. 이벤트가 있는 기록은 기존 익명 번호로 연결하고, 큐/잠금 대기와 상한 초과도 기존 비차단 수집으로 계측한다. context operation6·lane4의 detail1–7은 같은 소스 진단 동작이며 반복 억제도 해당 detail의 coalesced 계수로 남긴다. 구형 기록에 없으면 소스 상충 여부는 미측정이다. `bash scripts/test-source-evidence.sh`는 보존/재확인·정상 영문/편집·늦은 AX 응답·기한·대기/초과·엄격 수집을 대역으로 검사한다.

`captureBacklog`는 자동16/수동4 보호 구간, 종류별 제출16/구간별32요청의 고정 상한과 pendingAutomatic/pendingManual, 사유별 requested/merged/deferred/requestOverflow/windowOverflow/postOverflow/discardedOnDisable,submittedWindows/completedWindows를 제공한다. requested는 제출 예약에 성공해 worker가 처리한 요청, merged는 기존 구간에 연결된 요청, deferred는 새 보호 구간이 저장 간격 또는 앞선 미저장 구간 때문에 대기한 수다. postOverflow는 구간의 대표 trigger별 frame 수, discardedOnDisable은 OFF로 정리/취소된 미완료 보호 요청이다. completedWindows는 후속 쓰기 시도까지 처리된 구간 수이며 저장 성공은 storageBeforeWrite/현재 상태와 실제 파일을 함께 확인한다. 입력 callback은 즉시 자리 예약만 하며 별도 worker가 구간을 고정한다. 느린 writer도 구간 고정을 미루지 못한다. 새 자동 저장은10초 간격이고 준비된 구간을 한 묶음에서 사건 번호 순서로 발행한다. 미저장 이전 incident를 새 pre가 앞질러 기존 저장기의 retired가 되는 것을 막는다. 정상 종료는 간격 대기를 끝내고 남은 구간을 순서대로 저장하며 짧아진 post를 표시한다. OFF는 예약 쓰기를 취소하며 기존 파일을 유지하고 다음 ON에 종료된 세대의 구간을 섞지 않는다.

새 보호 정보가 있는 캡처에서 observationDelivery의 capture 생략은 즉시 별도 캡처를 합치거나 저장을 미룬 횟수다. 실제 정보 보존은 요청 목록·closed/후속 frame 초과·backlog/저장 상태를 함께 판단한다. 이 계수만으로 무손실을 주장하지 않는다. `bash scripts/test-diagnostics-impact.sh <새 출력 경로> --capture-only`는 보호 구간이 생성되는 반복 사건 부하의 ON/OFF4쌍을 비교한다. `Tests/Diagnostics/CapturePreservation`과 일반 진단 검사에서 ring 덮어쓰기/느린 writer 뒤 고정 전후 보존, 실제 후속/자동 저장 타이머, 묶음 순서, 독립 수동 자리, 제출/구간/frame 상한,OFF/정상 종료와 엄격 수집·원문 제외를 확인한다.

선택적 루트 `observationDelivery`는 `capacity`·`readCapacity`와 종류별 `processed`·`overflow`·`omitted`·`coalesced` 누적값을 제공한다. 코드는 `((operation-1)*8+(lane-1))*32+detail`이다. operation1–10은 event/readStart/readEnd/shape/state/context/sourceBoundary/marker/timer/capture, lane은 기존1–8이다. event detail은 누름1/놓음2/기타3에 consumed이면4를 더한다. state와 sourceBoundary는 기존 고정 상태/단계 코드다. capture detail1–5는 진행 중 같은 요청 묶음,9–13은10초 간격 제한,17은 수동32회 제한이며 각 trigger에 대응한다. 소스·전환 앞단 진단의 context detail 외 다른 detail은0이다. `overflow`는 자리 부족, `omitted`는 시작이 예약되지 않은 조회 종료·중복 종료·캡처 묶음/간격/횟수 제한, `coalesced`는 변화 없는 shape와 소스 진단의 반복 억제다. shape는 기존 AX snapshot을 메모리에서만 대조해 내용·정확한 커서/선택 범위의 변경 여부와 editing 상태를 고정 메타데이터로 기록한다. 원문·내용 해시·커서 좌표는 큐/파일에 넘기지 않는다. 각 엔진은 비교용 직전 문자열 참조 하나를 사용하며 새 수집 세대에서는 비교를 초기화한다. 같은 입력칸·UTF-16 길이·선택 유무·내용/범위·편집 상태가 반복되면 횟수로 묶되1초마다 기준 기록을 남긴다. 원문/범위 비교 표시가 없는 구형 관측은 동일 내용으로 해석하지 않는다. 최근 ring 덮어쓰기와 큐 상한이 가능하므로 coalesced/초과0만으로 분석 증거의 완전성을 보증하지 않는다. 실제 복구는 원래 snapshot의 본문/범위로 판단하고, 다른 이벤트/사유/소스/복구 상태는 별도 수집한다. 실제 잠금 경합과50ms 이상 큐 대기/시간 잘림은 같은 shape라도 개별 frame 또는 observationWait로 남긴다. 서로 다른 이유를 입력 손실로 합산하지 않는다. 계수는 제한된 묶음으로 반영하므로 늦을 수 있다. 요약기의 `observation_delivery`는 종류·단계·이벤트 edge/소비 여부를 해석하며, 구형 자료에 필드가 없으면 미측정으로 둔다. 기존 skippedEvents/skippedAuxiliary는 보조 집계이고 전체 생략 분류는 observationDelivery를 따른다. 기존/수동 파일과64파일/64MiB 자동 순환 계약은 유지한다. 제한된 최근 frame은 오래되면 덮어쓰며, 추가 메타데이터가 전체 실행·편집기 수신의 무손실을 보장하지 않는다.

shape frame의 선택적 `shapeEvidence`는 phase1=새 기준,2=주기/캡처 기준,3=종료 구간이다. `comparisonKnown`·`contentChanged`·`selectionChanged`는 구간 진입의 비교 결과이며 반복 checkpoint마다 새 변화가 발생했다는 뜻이 아니다. `editingChanged`·`editing`은 직전 수집 상태와의 편집 상태를 구분한다. 첫 관측·새 문맥/수집 세대·입력칸 변경은 비교 미확인으로 남긴다. `gap`은 샘플 번호 단절로 확인한 큐 초과 등의 비교 단절이며 내용·범위 변경 여부를 미확인으로 바꾼다. 비교 상태 재생성 등도 포함할 수 있어 gap만으로 큐 초과 원인을 확정하지 않으며 기존 종류별 overflow와 함께 해석한다. `firstMilliseconds`·`lastMilliseconds`는 실행 원점 이후 최초/마지막 성공 관측 시각, `observations`·`coalesced`는 구간 누계, `baselineSequence`는 최초 기준 frame 번호다. 마지막 관측 시각은 그 이후에도 같은 상태였음을 보증하지 않는다. 큐 초과 뒤 다음 성공 관측 전의 공백은 종류별 overflow와 마지막 시각으로 판단한다.

선택적 루트 `shapeBaselines`는 lane별 최대8개의 직전·현재 고정 기준을 ring과 독립 보관한다. 각 기준은 익명 field·길이·선택 유무와 구간 메타데이터만 포함한다. `active=false`는 편집/소스/문맥 경계에서 끝난 마지막 관측이며 새 shrink 판정에 사용하지 않는다. 반복 종료/문맥 경계에는 마지막 관측 시각으로 구간을 닫고, 캡처의 현재 기준은 최신 구간 누계를 보존한다. 구형 자료에 이 필드가 없으면 미측정이다. 수집/요약기는 임의 문자열·범위 좌표·알 수 없는 필드·잘못된 구간을 거부한다. `bash scripts/test-diagnostics.sh`의 shape 검사로 같은 길이 변경·커서/선택·편집·주기/종료·기준 덮어쓰기·실제 경합/초과·구형 호환을 대조한다.

shapeEvidence의 선택적 `ax`는 원문 없는 AX 의미 단서다. `valueClass`는0미측정/1빈값/2줄바꿈만/3유니코드 공백만/4그 외/5전체 분류 생략(4096 UTF-16 검사 예산 초과·앞부분 공백), `placeholder`·`label`은0미측정/1미지원·오류/2빈속성/3불일치/4앞뒤 공백을 뺀 일치 힌트다. 레이블은 title/description이며 일치해도 실제 입력과 우연히 같을 수 있다. `characterCount`는0미측정/1미지원·유효하지 않음/2AXValue UTF-16 길이 일치/3불일치, `representation`은0미측정/1원래 AXValue와 검증 표현 일치/2불일치다. 이 속성들은 같은 AX 제공자를 사용하므로 실제 편집기 문서의 독립 증명이 아니다. `route`는0미확인/1시스템 포커스/2실제 전면 앱 fallback/3조회 도중 경로 변경이다. `owner`·`window`는 익명 번호(창0은 미지원·미측정), `fieldRelation`·`windowRelation`은0미확인/1CFEqual/2다름이다. `identityEpoch`는 최대64개 입력칸·창·소유 문맥의 메모리 식별표 또는 진단 세대가 초기화될 때 증가하며 번호는 재사용하지 않는다. 실제 PID·CFHash·객체 주소·창 이름은 저장하지 않는다. 같은 해시만으로 입력칸 연속성을 인정하지 않으며, 창이 다르면 본문 비교를 미확인으로 남긴다. 같은 AX 객체가 편집기 내부에서 재사용되는 경우까지 실제 문서 동일성을 보장하지는 않는다.

추가 속성은 진단 ON의 기존 비동기 유휴 worker 한 건에만 포함하고, 미지원 batch 실패 시 원래 네 속성으로 재시도한다. 입력 callback·복구용 snapshot은 추가 IPC를 하지 않으며 기존 보류 한 건 제한·50ms AX 메시지 제한·소스/편집 revision/epoch/PID/50ms 전달 기한 검사를 유지한다. 진단 세대가 바뀐 응답의 추가 단서는 사용하지 않는다. 실패·지연 조회는 기존 AX read 시간/조회 실패 분기, 제출 초과는 shape 종류별 계수·샘플 단절로 남는다. 형태 분류는 최대4096 UTF-16 단위만 검사하며 긴 공백 prefix에서 뒤쪽을 추측하지 않고 code5로 생략 사유를 남긴다. 원문은 기존 snapshot 경로에서만 일시 비교하고 진단 큐에는 위 정수만 전달한다. 요약기의 `ax_interpretation`은 단서 이름과 `unverified_AX_provider_only`를 표시한다. 속성 없음은 구형·동기 관측의 미측정이며0으로 실제 본문/안내문을 단정하지 않는다.

일반 관측도 worker의 최초 try-lock 실패 여부, 획득 호출 전후 경과, 제출에서 worker 시작까지의 큐 지연을 구분한다. event/readStart/readEnd/shape/state/context/sourceBoundary/marker/timer와 캡처 전후 획득에 같은 계측을 적용하며, 입력 callback은 잠금 획득을 수행하지 않는다. 일반 frame의 선택적 `observationTiming`은 `queueMicros`·`lockWaitMicros`·`contended`·`clipped`, 루트의 `captureTiming`은 해당 전후 캡처의 계측이다. 기존 `durationMicros`는 실제 callback 또는 AX 조회 기간으로 유지한다. 잠금 획득 경과에는 스케줄링이 포함되며 입력 callback 대기·커널 순수 수면으로 해석하지 않는다. 단조 시계·마이크로초 미만 버림·60초 상한/초과 표시를 사용하므로 경합해도0µs일 수 있다.

`observationDelivery.waits`는 기존 종류별 코드에 처리/경합 건수·잠금 합계/최대·큐 최대·잘림을 누적한다. `processed`와 같은 worker 처리 시도를 세며, 일반 frame 억제와 이후 캡처 간격 거절도 별도로 유지한다. 캡처 processed/waits의 detail1–5는 직전 캡처 시도,25–29는 직후 캡처이며 trigger를 구분한다. omitted의 기존 진행 중 묶음/간격/수동 제한 코드는 유지한다. 변화 없는 shape도 경합하면 개별 frame을 남긴다. 일반 frame이 없는 타이머·억제/거절 경로와 캡처에는 실제 경합·잘림 또는50ms 이상 큐 지연을 `kind=9`의 고정 관측 대기 frame으로 보존한다. 이 frame의 category는 operation, edge는 detail이며 키·본문을 추가하지 않는다. 요약기의 `observation_lock_waits`·`observation_wait_totals`·`capture_timing`으로 구분하고 여러 파일의 누적값을 더하지 않는다. 구형 자료의 시간 필드 없음은 미측정으로 처리한다. 큐 초과·생략 계수 반영, 최근 frame 덮어쓰기와 저장 한도는 계속 적용된다.

메뉴의 <strong>입력 이상 진단</strong>으로 수집을 켜거나 끈다. 최초 기본값은 OFF이며 저장한 ON/OFF는 앱 재실행·Mac 재부팅 뒤에도 적용한다. 재부팅 뒤 자동 시작 여부는 별도의 ‘로그인 시 자동 실행’ 설정을 따른다. 켜진 동안 <strong>방금 입력 누락 기록</strong>을 사용할 수 있고 <strong>진단 로그 폴더 열기</strong>로 로컬 자료를 확인한다. 기본 위치는 `~/Library/Application Support/HanQ Diagnostics/InputIncidents`다. 끄면 새 수집·지연 후속 캡처를 중단하고 저장 파일은 삭제하지 않는다. 다시 켤 때 이전 메모리 구간·진행 중 AX 조회를 새 구간에 섞지 않는다. 저장 준비·큐 정리는 백그라운드에서 수행한다.

기본 폴더에서는 최대128KiB의 소유 관리 색인과 최대16KiB 상태 파일을 이어받아 재실행 뒤에도 같은 자동64파일·64MiB 예산을 유지한다. 관리한 자동 파일만 오래된 전후 묶음부터 순환하며 수동 파일은 제외한다. 기존 임시/개발 폴더는 이전 자료로 보존한다. 색인·파일의 소유자/권한/동일성 불일치·손상·중단된 발행의 모호한 파일에는 자동 저장을 중단해 보존과 한도를 우선하고, 수동 저장은 독립적으로 시도한다. 색인이 없는 폴더의 기존 파일을 자동 관리 대상으로 추정하지 않는다. 저장 상태의 성공/삭제 계수는 이 관리 구간에서 재실행을 넘어 누적하고, 관측·분기 계수와 시각은 실행별로 해석한다. 캡처의 선택적 `runID`는 매 실행마다 새로 만든 익명 UUID다. 같은 실행의 중복 frame은 `(runID, sequence)`, 이벤트 연결은 `(runID, event)`로 구분하며 서로 다른 실행의 계수·상대 시각·이벤트를 합치지 않는다. 구형 자료에 없으면 실행 구분 미측정으로 처리한다. UUID는 기기·사용자 식별자가 아니며 다음 실행에 재사용하지 않는다.

개발용 `--diagnose-input-incidents <전용 디렉터리>`는 저장 설정을 바꾸지 않고 해당 실행에서만 최근 입력 처리 메타데이터를 제한된 메모리에 보관한다. 같은 문구를 반복 입력할 필요 없이 평소 사용 중 발생한 이상을 조사하는 용도다. 권한 사전 체크를 완료한 같은 앱을 종료한 뒤 LaunchServices로 실행하고 새 프로세스의 권한을 다시 확인한다.

```sh
incident_dir=$(mktemp -d /private/tmp/hanq-input-incident.XXXXXX)
open -n build/candidate/HanQ.app --args --diagnose-input-incidents "$incident_dir"
python3 scripts/prepare-app-test.py check <동일-앱의-권한-record.json>
```

이 실행의 한Q 메뉴에는 **방금 입력 누락 기록**이 나타난다. 누락을 발견하면 메뉴를 한 번 선택해 직전 기록과 약 1초 뒤 기록을 남길 수 있다. 입력 처리·AX 조회의 긴 지연이나 설명되지 않은 본문 길이 감소, 전환 대기열의 실패·미전달 보관도 의심 구간으로 자동 저장한다. 길이 변화가 없는 누락은 자동 감지만으로 잡지 못할 수 있으므로, 정상 회차나 자동 기록이 없다는 사실을 무손실의 근거로 사용하지 않는다.

입력 본문·키 값·클립보드·앱 이름은 저장하지 않는다. 기존 이벤트 경로의 시각·분류·통과/소비 여부, 기존 AX 조회의 시작·끝, 본문 길이와 선택 유무·익명 입력칸 번호, 보정 상태·보관 개수, 전환 대기열과 첫 자음 전달 확인의 단계·대기 개수, 기존 판단의 본문·커서·조회·전달 확인 등 고정 대기 사유만 기록한다. 같은 대기 사유는 바뀔 때 한 번만 기록한다. 추가 속성 조회는 위 비동기 유휴 batch에 한정하며 탭·키 재전송·입력 소스 변경은 하지 않는다. `--diagnose-input`의 반복 권한 조회·동기 로그 없이도 독립적으로 사용할 수 있다.

입력 callback은 진단 잠금이나 파일 저장을 기다리지 않는다. 최대 4,096개 기록을 유지하고 전용 백그라운드 큐에서 저장한다. 자동 기록은 10초 간격을 유지하면서 횟수 제한 없이 이어가고, 메뉴로 켠 기본 폴더의 관리 자동 파일 또는 개발용 옵션의 현재 실행 자동 파일만 최대 64개·합계 64MiB 안에서 오래된 전후 구간 묶음부터 순환 삭제한다. 수동 표시는 기존의 실행당 32구간 제한을 유지하며 순환 삭제하지 않는다. 관리 대상으로 확인되지 않은 기존 파일은 이름·생성 시각과 무관하게 보존하므로 전체 폴더 크기는 자동 기록 한도보다 클 수 있다. 개발용 옵션은 실행마다 새 전용 폴더를 사용하고 보존 자료의 정리는 별도로 결정한다. 디렉터리·파일은 사용자 전용 권한을 사용하며 기존 파일·심볼릭 링크를 덮어쓰지 않는다. 완성 파일을 임시 파일에서 원자적으로 발행한 뒤 교체하므로 저장 중에는 파일 하나의 임시 여유 공간이 추가로 필요하다. 파일·폴더의 소유자·권한·동일성이 바뀌거나 저장/삭제에 실패하면 자동 저장을 생략하며, 한도를 넘겨 계속 쌓지 않는다. 삭제된 구간의 늦은 후속 파일은 다시 만들지 않는다. 경합·용량 제한으로 기록이 생략될 수 있고 이벤트 연결도 보조 정보다. 이벤트 관측 생략은 단계별 누적 개수로 구분하며 비동기 계수 반영이 늦을 수 있다. 수동 저장 요청은 경합 중에도 백그라운드에서 보존한다. 최종 이벤트 경계의 통과는 대상 편집기의 수신·IME 반영 확인을 대신하지 않는다.

```sh
python3 scripts/summarize-input-incident.py "$incident_dir"/incident-*.json
```

요약은 단계별 관측 개수·지연·AX 조회 겹침을 보여준다. 개수 차이나 조회 겹침만으로 누락·원인을 확정하지 않으며, 의도한 보관·소비·상태 반영 이벤트와 구분해 대조한다. 일반 수집은 메뉴의 ‘입력 이상 진단’을 OFF로 바꾸어 종료한다. 개발용 옵션으로 켠 실행은 옵션 없이 다시 시작하면 저장된 ON/OFF를 따른다. OFF를 저장해 두면 다음 일반 실행에서도 수집하지 않는다.

저장 결과는 각 캡처의 선택적 `storageBeforeWrite`와 관리 구간별 `.storage-<UUID>.status`로 구분한다. 캡처 헤더는 현재 파일을 쓰기 전 완료된 저장 상태이며, 상태 파일은 현재 시도까지 반영한다. 성공·한도·폐기·저장 불가·인코딩 실패 횟수, 실제 순환 삭제 구간/파일/바이트, 현재 자동 사용량과 한도, 마지막 시도 좌표·결과·고정 실패 단계/errno, 캡처 발행 시간과 최댓값·60초 잘림, 상태 파일 쓰기 실패 횟수를 기록한다. 발행 시간에는 캡처 JSON 인코딩과 상태 파일 자체 쓰기를 포함하지 않는다. 결과 코드는0 미시도/1 저장/2 한도/3 폐기/4 저장 불가/5 인코딩 실패, 실패 단계는0 없음/1 인자/2 폴더/3 소유 파일 확인/4 발행/5 순환 삭제/6 인코딩이다. 폴더·파일 경로와 임의 오류 문구·입력 내용은 상태에 넣지 않는다.

상태 파일은 writer당1개·최대16KiB로 독립 제한하며64개·64MiB 자동 캡처 예산과 구분한다. 전용 백그라운드 writer에서 소유자·권한·파일/폴더 동일성을 검사하고 원자적으로 교체한다. 기본 폴더는 검증된 같은 관리 구간의 상태만 이어받으며, 개발용 실행의 이전 상태와 외부 변경 파일은 덮어쓰지 않는다. 디스크 전체가 쓰기 불가능하면 그 실패 자체도 즉시 파일에 남길 수 없으므로 마지막 정상 상태를 유지하고 다음 정상 저장에 누적 실패를 반영한다. 파일 시각·마지막 incident와 함께 최신성을 확인한다. 수집 도구는 종료 시 상태 파일을 별도 자료로 최대16개·각16KiB 수집하고 기존 캡처를 새 입력 관측으로 세지 않는다. 요약기는 상태 파일의 `storage_after_write`, 캡처의 `storage_before_write`를 구분하며 구형 누락은 미측정이다.

반복 분기의 개별 기록 억제도 `decisionDelivery.coalesced`에 기존 위치/사유/이벤트 코드별로 누적한다. 실제 잠금 경합뿐 아니라50ms 이상 큐 지연·시간 잘림이 있으면 같은 유휴 사유도 개별 보존한다. 요약기의 `decision_delays`·`observation_delays`는 큐만 지연된 경우까지 표시하며, 기존 `decision_lock_waits`·`observation_lock_waits`는 실제 try-lock 실패만 표시한다. 모든 누적 계수는 파일별로 더하지 않는다.

저장 정책은 `DiagnosticLogRetentionPolicy`, 파일 저장·순환은 `DiagnosticLogStore`로 수집기와 분리한다. 사용량과 저장/한도/폐기/실패 결과를 제공하므로 향후 사용자용 진단의 별도 한도·명시적 저장·검토/내보내기에 재사용할 수 있다. 현재 메뉴는 로컬 수집 ON/OFF와 수동 시점 표시를 제공한다. 상세 개발 진단을 그대로 사용자 내보내기 형식으로 삼지 않으며, 사용자용 수집 범위·보존 기간·검토/제출 UI는 별도 설계한다. `scripts/test-diagnostics.sh`는 순환·기존/수동 보존·원자적 발행·실패 경로와 32회 이후 저장 지속, 저장된 ON/OFF·실시간 전환·재시작 순환과 구간 격리를 검사한다.

### 진단 ON/OFF의 통제 입력 영향 비교

`bash scripts/test-diagnostics-impact.sh`는 제품의 키 필터·첫 자음 입력 게이트·불일치 엔진과 진단 writer를 사용해 같은 합성 이벤트를 OFF→ON/ON→OFF 순서로 반복한다. 별도 프로세스에서128키를 예열하고8/20/40ms 입력, 보관/재전달·미전달 보존,60ms 진단 잠금 보유, 실제 저장·순환 부하를 비교한다. 샘플링 타이머를 포함하고 출력은 새 시험 폴더에 둔다. 전역 이벤트 탭·실제 키 전송·입력 소스 변경·실제 AX/사용자 입력칸은 사용하지 않는다. AppKit 이벤트 객체 생성이 가능한 일반 터미널 환경에서 실행한다.

처리/통과/소비/재전달/보관과 순서·확인 수, AX/소스 조회 횟수의 완전 일치와 실패0을 확인한다. 콜백 원시 시간·50/95/99백분위·최대, 계획 입력 간격의 지연과 전체 처리 시간을 함께 남긴다. 기본 로컬 판정 예산은 쌍별 추가99백분위의 중앙값1ms 미만,1ms 이상 차이가 반복되면 재분석,ON 콜백50ms 이상 중단 없음이며60ms 잠금 보유 중에도 콜백이 반환되는지 별도로 확인한다. 이 수치는 해당 통제 시험의 성능 예산이며 모든 기기·편집기의 지연 보증이 아니다. 머신 부하·단발 이상치와 진단 때문에 반복되는 악화를 구분하고 실패한 실행도 보존한다. 결과는 원본 이벤트를 OS에 넣은 앱 전체/IME/편집기 수신·물리 키 시험과 구분한다.

### 진단 CPU·저장소 영향 확인

입력 callback 지연과 프로세스 전체 CPU·I/O는 별도로 검증한다. 같은 설치본·같은 전면 앱과 입력 조건에서 ON/OFF 순서를 교차하고 전환 직후·예열·스택 수집 구간을 제외한다. OFF 전에 필요한 메모리 구간을 수동 기록하고 후속 저장 완료·기존 파일 백업을 확인한다. 정상 관측과 사건 캡처의 쓰기 비용도 나눠 비교하고 종료 시 설정을 복원한다.

macOS `proc_pid_rusage`의 CPU 누계는 Mach tick이므로 `mach_timebase_info`로 초 환산하고 `ps time` 증가와 대조한다. 디스크 읽기/쓰기와 논리 쓰기는 별도 계수이며 캐시·메타데이터 호출 전체나 SSD 장치 전체 I/O로 확대하지 않는다. 파일 수/크기/수정 시각과 저장 시도 계수도 함께 확인한다. 자동64파일/64MiB는 보관 한도이며 누적 쓰기량 제한이 아니다. 대기 스레드까지 포함한 `sample` 스택의 빈도를 함수별 CPU 비중으로 환산하지 않는다.

진단 OFF에도 두 복구 엔진의20ms 관측 타이머와 안전한 AX·포커스 조회는 유지된다. ON은 기존 비동기 조회의 추가 의미 속성과 변화 비교·제한 큐·통계를 수행하므로 CPU가 늘 수 있다. 현재 후보의 ON/OFF 비교에서 추가 CPU를 확인했으며 CPU·I/O 최적화는 이번 진단 보강의 입력 정확성·지연 검증과 구분한다. 사용자 앱·IME·물리 타자·재부팅과 프로세스 자체 측정의 확인 범위를 명시한다.

- `scripts/test-watchdog.sh`: 응답 중단 시 종료
- `scripts/test-permission-monitor.sh`: 권한 감시 실패·중단 경로
- `scripts/test-recovery.sh`: 권한 상실 후 재실행과 반복 방지

LaunchServices를 통한 실제 재실행 경로는 별도로 검사한다.

```sh
bash scripts/test-recovery-app.sh
```

자동 검사만으로 물리 키 입력과 대상 편집기의 IME 동작을 검증할 수는 없다. 변경한 기능에 따라 실제 우측 키 입력, 한자 후보 확정·취소, 붙여넣기·Undo·클립보드 복원, 권한 철회·재허용을 확인한다.

텍스트 변환의 요청·선택 준비·정상 중단 등 상세 과정은 `--diagnose-input` 모드에서만 기록한다. 대상 앱 식별자는 상세 로그에서 제외한다. AX 읽기 실패·선택 반영 시간 초과·편집 결과 확인 실패와 권한 안전 종료·입력 소스 전환 실패는 일반 실행에서도 시스템 로그에 남긴다. 입력 문자열과 클립보드 내용은 기록하지 않는다.

권한 문제는 [run-app-input-diagnostic.py](../scripts/run-app-input-diagnostic.py)로 LaunchServices를 통해 재현한다. 터미널 자식으로 직접 실행하면 일반 앱 실행과 권한 조회 결과가 다를 수 있다. 앱에 전달하는 진단 로그는 임시 폴더에 쓰고 감독 도구가 종료 시 `--output` 폴더로 복사한다. 사용 가능한 옵션은 다음 명령으로 확인한다.

```sh
python3 scripts/run-app-input-diagnostic.py --help
```

### 재현 상태 보존

이미 문제가 재현된 브라우저·편집기 창과 탭은 유지한다. 원인 비교가 끝나기 전에 페이지 새로 고침, 창·탭 닫기, 브라우저·입력기 재시작, 입력 소스 초기화를 수행하지 않는다. 우선 기존 진단 로그·코드·입력 전송 대역으로 실패 경로를 검증한다. 상태 변경이 필요한 시험은 기존 재현 상태와 구분하고 사용자 요청 범위에서 별도로 수행한다. 새 빌드의 권한 사전 체크도 재현 상태를 보존할 수 있는 별도 시험 환경에서 진행한다. 기존 프로세스의 상태를 읽을 때 앱을 여는 기능이 있는 조회 명령을 사용하지 않는다. PID·실행 경로·본문·선택을 먼저 기록하며, 창 활성화도 입력 문맥에 영향을 줄 수 있으므로 활성화 전후와 키 입력 후를 분리한다. 같은 창의 추가 재입력이 기존 코드로 성공하면 새 수정의 효과로 기록하지 않는다. 별도 엔진으로 지정한 구간의 복구, 설치 앱의 자동 감지·복구, 새 시험 창의 성공을 구분한다.

## 베타 검증 운영

0.3.0 베타의 물리 키·키보드별 실사용 확인은 배포 후 사용자 피드백으로 보완한다. 모든 키보드의 물리 입력 확인을 베타 배포의 선행 조건으로 두지는 않는다. 자동 검사와 실제 앱에서 합성 키로 확인한 결과, 사용자가 직접 키를 눌러 확인한 결과는 구분해 기록한다. 배포 전 빌드·설치·업데이트 검사는 [배포 안내](RELEASE.md)를 따른다.

피드백에는 앱·입력 소스·키보드 종류와 모델·재현 순서·기대 결과·실제 결과를 함께 받는다. 새로 접수한 문제는 기존 검증 결과와 대조하고 재현 여부와 영향 범위를 확인해 후속 수정으로 관리한다.

## 지원 범위와 추가 검증

한국어 입력기 지원 범위는 모든 기능에 공통으로 적용하는 [지원 정책](SPEC.md#한국어-입력기-지원-정책)을 따른다. 아래 항목은 앱·물리 키·환경별 동작을 확인하기 위한 추가 검증 대상이다. 알려진 호환성 문제는 각 기능 명세에서 관리한다.

최소 배포 대상은 macOS 13이며 안내 대상은 Apple Silicon이다.

로그인·재부팅 후 자동 실행, 중복 실행 방지 및 잠자기·깨우기 후 정상 동작은 사용자 환경에서 확인 완료했다. 이 확인 결과를 2026-10-16에 문서에 반영했으며, 이 날짜는 실제 검증일을 뜻하지 않는다. 실행 중 다시 열기 요청이 60초 안에 3회 누적될 때의 안내는 위 메뉴바 항목 복구 검증에서도 실제 앱으로 확인했다. 이 결과를 다른 OS·장치 조합이나 모든 후속 빌드의 자동 검증 결과로 확대하지 않는다. 관련 구현 변경 시에는 회귀 검사를 수행한다.

- 여러 macOS 버전에서 입력·손쉬운 사용 권한·Caps Lock 설정 동작.
- 지원 입력 소스별 실제 입력·붙여넣기·Undo, 편집기별 한자 확정·취소와 원문 중복 보정.
- 클립보드 복원, 자판 자료 조회 실패, 입력 도중 포커스·입력 소스 변경 시 편집 취소.
- 내장·외장 키보드, 장시간 실행과 권한 철회 후 입력 복구.
- 권한 검사 보조 프로세스를 포함한 CPU·메모리·wakeups·전력 영향.

단기 CPU 관측을 배터리 사용량으로 환산하지 않는다. 성능 측정 도구는 `scripts/measure-energy.sh`다. 결과를 공유할 때는 다른 프로세스나 개인 환경 정보가 포함되지 않았는지 확인한다.

변경 사항을 제출할 때는 PR 본문에 실행한 검사·환경·관측 결과·미검증 항목을 요약한다. PR을 만들기 전에는 로컬 작업 기록으로 보관한다. 원본 로그는 개인 환경 정보와 입력 내용이 없는지 확인한 뒤 필요한 부분만 공유한다.

## 문서 갱신

사용자에게 보이는 기능·사용 조건은 README에, 빌드·구현·진단 절차는 이 문서에 반영한다.

README는 현재 기능·사용법·동작 조건을 안내한다. 버전별 추가·개선 내역은 CHANGELOG와 릴리스 노트에서 관리하며, README의 다운로드·변경 내역 링크는 특정 버전에 고정하지 않는다. 서명 방식 전환처럼 설치·권한 호환성을 설명하는 데 필요한 버전은 명시할 수 있다.

공개 문서에는 재현 가능한 절차·검증 요약·알려진 제한을 유지한다. 후보별 상세 실험과 개인 작업 기록은 공개 문서에 누적하지 않는다. 배포 절차와 담당은 [배포 안내](RELEASE.md)를 따른다.

현재 공개본과 개발 후보의 동작이 다르면 README·사이트에서 적용 버전을 구분한다. SPEC·이 문서의 현재 구현 설명은 커밋된 개발 후보를 기준으로 하며, 미커밋 로컬 변경을 포함한 시험은 차이와 검증 범위를 따로 기록한다. 과거 릴리스 노트·검증 기록은 당시 사실을 유지하고, 옮긴 기록의 링크와 현재 상태를 가리키는 안내만 보완한다.

문서 전체 점검은 루트 안내·변경 이력·LICENSE, `docs/`의 명세·개발·배포·버전·릴리스 문서, DMG 안내, 사이트·업데이트 창용 노트·이용 조건을 목록화한다. 별도 비공개 저장소는 그 저장소의 지침·계획·작업 목록·타임라인·과거 검증 기록을 따로 목록화한다. 전체 로컬 렌더링·상대 경로/앵커 검사와 현재 소스·버전·피드 대조를 수행하며, 과거 기록의 현재형 표현을 최신 결과로 바꾸지 않는다. 소스 커밋 여부·공개 여부·검증 수준을 구분하고, 원격 링크의 현재 접근 여부와 실제 앱 시험은 실행한 경우에만 확인 완료로 기록한다.

### 전환 시각과 실제 설치본 복구 검증

`bash scripts/test-source-timestamps-native.sh <record.json> <새-결과-디렉터리>`는 권한 검사를 마친 설치본을 별도 소유 시험창에서 검증한다. 고정 영문 접두부·실제 우측 Command 전환·두벌식 조합과, 시험창이 원래 키만 영문으로 출력하는 조건에서 자동 복구 결과·커서를 확인한다. 합성 키는 소유 프로세스가 활성 상태일 때만 HID로 보내며 대상/권한/보안 입력 변경에는 중단하고 시험에서 누른 키만 해제한다. 기존 사용자 본문은 조회하거나 지우지 않고 선택 입력 소스를 복원한다. 저장하는 본문은 시험 도구의 고정 문자열뿐이다. 실제 물리 키와 사용자 편집기의 자연 재발 확인은 별도다.

HID 원본 시각과 session 시각은 같은 정수형이라는 이유만으로 직접 비교하지 않는다. 원본 입력·우측 Command/Caps Lock 경계는 HID 진입부에서 단위를 통일하고 일반 전환을 소비할 때도 그 경계를 한 번 인수한다. 자동 검사는125/3·1/1 timebase, HID tick/이미 나노초인 합성 입력의 혼재와 미래 시각 거부, 실제 이전 키·뒤에서 시각이 바뀐 키·오버플로와 전환 뒤 이력 인계의 전체 본문/선택 검사를 포함한다.


### 긴 본문 입력·전송 소유권 검증

`Tests/LongDocumentInput/`의 [사용 안내](../Tests/LongDocumentInput/README.md)에 따라 새 권한 검사를 마친 정확한 앱을 시험한다. `bash scripts/test-long-document-input.sh <record.json> <새-결과-폴더>`는 전용 합성 본문에서 일반 입력과 전환·복구를 확인한다. `bash scripts/prepare-long-document-physical.sh <record.json> <새-결과-폴더>`는 사람이 직접 누르는 8단계 시험창을 준비하며 키를 자동 전송하지 않는다. 시험창 성공을 타사 앱·물리 키 성공이나 자연 버그의 발생 빈도로 확대하지 않는다.

합성 키와 입력 소스 변경은 전역 동작이므로 다른 타자·포커스 이동과 겹치지 않는 전용 시간을 사용한다. 매 키와 소스 변경 전에 실제 시스템 키보드 포커스 소유 PID·전면 앱·보안 입력·권한·제품 신원을 새로 확인한다. 포커스 상실에는 전송을 중단하고, 원래 소스 복원도 소유 시험창에서만 허용한다. 실제 전송 시각·keyDown 진입·처리 반환·최종 결과 확인을 구분하며 본문·커서·소스·키 수가 맞고 기록이 잘리지 않은 결과만 대응한다. 사용자 문서·클립보드 내용은 수집하지 않는다.

`bash scripts/test-long-document-source-guards.sh`는 이 소유권·기한·포커스 조건을 기본·최적화 컴파일의 대역으로 검사한다. `test-mismatch-recovery.sh`의 `high-speed-proof`는 정상 지연 입력의 구성 자모 필요조건과 기존 완전 증명을 함께 검사한다. 포커스·문자열 비교 검사는 원래 Swift 정규 동등성을 독립 기준으로 사용하고 긴 동일 접두부·다른 정규 표현·서로게이트·NUL·변경된 접미부를 포함한다. 이 자동 검사는 실제 AX·IME·물리 키 검증과 구분한다.
