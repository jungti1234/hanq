# 한Q 제품·기술 명세

한Q는 macOS 기본 입력기를 유지하면서 한영 전환과 한국어 텍스트 편집을 보조하는 메뉴바 앱이다. 이 문서는 기능의 동작 계약과 구현 제약을 정의한다. 사용 안내는 [README](../README.md), 빌드·코드 구조·검증 방법은 [개발 안내](DEVELOPMENT.md)를 참고한다.

## 제품 범위

- 우측 Command를 통한 한국어·영어 입력 소스 직접 전환
- 우측 Option을 통한 선택 영타 변환, 자모 합치기, Apple 한자 후보 호출
- 실제 입력 소스 변경에 따른 이름 표시(HUD)
- 메뉴바의 기능별 설정, 시스템 Caps Lock 전환 설정 연동, 로그인 시 자동 실행
- 손쉬운 사용 권한 안내, 입력 감시 중단 방어와 권한 상실 후 복구
- 앱 정보·라이선스 표시와 사용자 제출 방식의 피드백 폼

실시간 한글 조합과 한자 후보 UI는 macOS 입력기에 맡긴다. 자모·영타 변환은 사용자가 명시적으로 요청한 기존 텍스트에 적용하며, 아래 첫 자음 조합 보정과 입력 소스 불일치 복구를 자동으로 수행한다. 자체 IME·한자 사전, 문맥에 따른 자동 언어 추정, 범용 키 리매핑, 앱별·입력창별 언어 기억, 입력 내용 수집은 제품 범위에 포함하지 않는다.

## 한국어 입력기 지원 정책

한Q의 지원 대상은 Apple이 macOS에서 공식 제공하는 한국어 입력기 전체다. 현재 관리 대상은 두벌식·세벌식·세벌식 390·공진청 로마자·한컴 로마자이며, Apple의 공식 제공 목록이 바뀌면 구현·검증 대상을 함께 갱신한다. 여기서 입력기는 물리 키보드 기종과 별개다.

이 지원 범위는 모든 기능에 공통으로 적용한다. 기능을 추가하거나 변경할 때도 같은 범위를 기준으로 구현·검증한다. 배열을 확인할 수 없을 때의 안전 조건과 대체 동작은 해당 기능 명세를 따른다.

앱·물리 키·macOS 환경별 검증 범위와 알려진 호환성 문제는 각 기능 명세와 [추가 검증 항목](DEVELOPMENT.md#지원-범위와-추가-검증)에서 관리한다.

## 외부 키보드의 키 확인

설정 창 제목은 ‘한Q - 외부 키보드 설정’이다. 한Q 로고 옆에 ‘외부 키보드의 한영키·한자키를 설정해주세요’ 안내와 작은 키보드 아이콘·기기명을 표시한다. 한영키·한자키는 두 개의 행으로 구분하고 현재 등록 단계와 완료 상태를 표시한다. 사용자에게 보이는 표기는 ‘한영’으로 통일한다.

입력 기능과 손쉬운 사용 권한이 활성화된 동안, IORegistry에서 USB·Bluetooth 외부 키보드가 감지되고 저장된 설정이 없으면 한영키·한자키 확인 창을 표시한다. 시작 시 이미 연결된 키보드도 포함한다. 내장·가상 키보드와 외부 여부가 불명확한 기기는 자동 설정 대상에서 제외한다.

- 한영키와 한자키를 차례로 한 번씩 누르고 놓은 뒤 저장한다. 서로 다른 두 키가 모두 확인되기 전에는 저장하지 않는다. 기존 설정을 다시 지정하다 취소하면 이전 설정을 유지한다.
- 오른쪽 Command·Option·Control·Shift, macOS에 전달되는 언어 키(102·104), 메뉴 키만 지정할 수 있다. 왼쪽 보조키·일반 문자·스페이스·방향키·F1–F20·Caps Lock·Fn·조합 키는 지정하지 않는다. 기존 저장 설정에도 같은 제한을 적용하며 허용되지 않는 키가 포함된 설정은 불러오지 않고 다시 등록한다. 좌우 판정은 물리 위치가 아닌 macOS 키 신호를 기준으로 한다. 키 확인은 해당 기기에서 온 이벤트만 받으며, 창이 전면일 때만 입력을 소비한다.
- 설정 창에 포커스가 있을 때만 한Q의 전환·편집 요청을 중지한다. 다른 창이나 앱을 클릭해도 설정 창과 완료한 단계는 유지하고, 아직 놓지 않은 키의 등록만 취소한다. 배경에서는 키를 등록하지 않으며 기존 한Q 기능은 계속 사용할 수 있다. 사용자가 ‘나중에’를 누르면 키 설정을 완료하지 않을 경우 한영키·한자키가 올바르게 작동하지 않을 수 있다는 확인창을 표시한다. 기본 버튼인 ‘설정 계속하기’는 등록한 단계를 유지하고 돌아가며, ‘나중에 설정하기’를 선택해야 설정 창을 닫는다. 확인창에서는 키를 등록하거나 한Q 기능을 실행하지 않는다. 별도 닫기 버튼은 제공하지 않는다. 보안 입력·권한/정책 제한·기기 분리 시에는 미완료 설정을 폐기한다. 이미 소비한 누름에 대응하는 놓음은 창 닫힘 뒤에도 처리하며 기능을 실행하지 않는다. 이벤트 탭 해제 시 모든 상태를 정리한다.
- ‘나중에’로 미루면 앱이 실행되는 동안 같은 기기를 자동으로 다시 안내하지 않는다. 저장한 설정이 없으므로 다음 앱 실행에서는 다시 안내할 수 있다. 메뉴 맨 위 상태 표시 아래에 구분선과 ‘외부 키보드 설정’을 배치하며, 외부 키보드가 한 대 이상 감지될 때만 두 항목을 함께 표시한다. 마지막 외부 키보드가 사라지면 두 항목을 숨긴다. 해당 메뉴에서 연결된 기기를 다시 지정할 수 있다.
- 기기 식별은 제조사·제품·연결 방식·제품명 및 일련번호(없으면 연결 위치)를 해시한 값으로 로컬 저장한다. 일련번호 원문·키 입력 이력은 저장하지 않는다. 일련번호 없는 기기의 포트 변경이나 USB/Bluetooth 전환은 새 기기로 인식될 수 있다. 일련번호 없는 동일 모델을 같은 연결 위치에 번갈아 연결하면 기존 설정이 재사용될 수 있다. 일련번호와 연결 위치가 모두 없으면 현재 연결의 서비스 ID를 해시해 사용하므로 재연결 시 다시 등록한다. 구분할 수 없는 동일 식별 기기가 동시에 연결되면 설정과 사용자 지정 매핑을 적용하지 않는다.
- 저장한 기기의 한영키는 누를 때, 한자키는 놓을 때 기존 기능을 실행한다. 기능별 ON/OFF·보안 입력·편집 안전 조건은 유지한다. 등록하지 않은 기기와 내장 키보드는 기본 매핑을 사용한다.
- 기기별 이벤트 연결은 비공개 Quartz 필드 87을 별도 파일에 격리해 사용한다. 현재 열거된 키보드 서비스 ID와 정확히 일치할 때만 인정하며 최근 입력 기기 등으로 추정하지 않는다. 저장된 외부 키보드가 연결된 상태에서 이벤트의 기기를 식별하지 못하면 해당 이벤트에는 기본·사용자 지정 매핑 모두 적용하지 않는다. 이 경우 일부 내장 입력도 기본 기능을 사용할 수 없다. 실제 물리 입력과 macOS 버전별 확인이 필요하다.
- 두 키보드에서 같은 쪽 modifier를 동시에 누르면 전역 flags만으로 개별 놓음을 확정할 수 없는 경우가 있다. 이때 한자 동작을 추정 실행하지 않고 전체 놓음에서 잔여 상태를 정리한다.
- HID 장치 독점, 시스템 키 매핑 변경, 일반 입력의 버퍼링·재생은 하지 않는다. 이벤트 탭으로 전달되지 않는 물리 키는 현재 등록할 수 없다.

## 한영 전환

입력 소스는 TIS의 언어 정보(`ko`, `en`)로 분류하고 ID로 식별한다. 표시 이름으로 전환 대상을 판정하지 않는다.

| 현재 입력 소스 | 우측 Command의 전환 대상 |
| --- | --- |
| 한국어 | 마지막으로 사용한 영어 입력 소스 |
| 영어 | 마지막으로 사용한 한국어 입력 소스 |
| 그 밖의 언어 | 마지막으로 사용한 영어 입력 소스 |

마지막 입력 소스 ID는 시스템 경로로 변경한 경우에도 갱신하고 앱 재시작 후 유지한다. 기억한 소스를 사용할 수 없으면 해당 언어의 활성·선택 가능한 소스 중 영어는 ABC, 한국어는 두벌식을 우선하고, 없으면 같은 언어의 다른 소스를 사용한다. 현재 소스를 읽지 못하거나 대상 언어가 없으면 우측 Command의 원래 동작을 유지한다.

전환 요청은 `TISSelectInputSource`를 사용한다. 앞선 입력·선택의 반영 확인과 후속 키 보관은 아래 전환 대기 명세를 따른다. 이 선택 보존 단계 자체는 시스템 전환 단축키를 합성하지 않는다. Apple 한국어 입력기에서 전환할 때 읽기·선택 변경이 가능한 텍스트 입력칸에 명시적 선택이 있으면, 소유 프로세스에 왼쪽 방향키 누름과 놓음을 한 쌍 보내 조합을 확정한다. 시작 커서 반영을 확인한 뒤 전환하고 원래 선택을 복원한다. 포커스·본문·선택·입력 소스·권한이 유지되는 경우에만 복원하며 본문·클립보드는 쓰지 않는다. AX 요청별 10ms 제한과 준비 단계 60ms 한도를 적용한다. 커서 이동은 한 번만 전송하고 40ms 확인 구간에서 같은 포커스·원문·소스와 커서 반영을 검사한다. 이 구간의 일시적인 포커스·본문 조회 실패는 기한 안에서 재확인하며, 실제로 다른 포커스나 본문이 확인되면 중단한다. 진행 중인 AX 요청 시간만큼 종료가 늦어질 수 있다. sleep과 run-loop 재진입은 하지 않는다. 전송 후 확인이 실패하면 전환·선택 복원을 강행하지 않는다. 선택 API의 성공이나 소스 변경 알림을 대상 편집기의 IME 준비 완료로 간주하지 않는다. 빠른 전환 직후 첫 글자의 정확성은 실제 입력으로 검증한다.

## 한자키의 텍스트 처리

한자키 사용 설정이 ON이면 우측 Option을 놓는 시점에 다음 순서로 처리한다. 영타 변환과 자모 합치기는 현재 입력 언어에 관계없이 적용한다.

1. 명시적 선택이 영타 변환 조건에 맞으면 한글로 변환한다.
2. 그 외에는 선택 영역 또는 커서가 속한 문단의 분리된 자모를 합친다.
3. 자모 변환으로 달라지는 내용이 없고 Apple 한국어 입력기가 활성화되어 있으면 한글 대상의 한자 후보창을 요청한다.

텍스트나 선택 범위를 읽을 수 없거나 변환 조건을 만족하지 못하면 편집하지 않는다. 읽기 실패를 무조건적인 한자 호출로 대신하지 않는다.

### 선택 영타 변환

선택 영역에 ASCII 영문자가 하나 이상 있고 나머지가 ASCII 인쇄 가능 문자 또는 탭·CR·LF일 때만 변환한다. 선택이 없거나 비ASCII 문자가 섞인 선택은 영타 변환 대상이 아니다.

변환 대상 배열은 현재 한국어 입력 소스의 ID로 결정한다. 현재 소스가 다른 언어이면 마지막으로 사용한 한국어 소스가 활성·선택 가능한지 확인하고 해당 ID를 사용한다. 현재 소스를 읽지 못하거나 한국어 사용 이력이 없거나 기억한 소스가 제거·비활성화된 경우에는 두벌식으로 변환한다. 영타 복구의 기본값은 두벌식이며, 한영 전환의 다른 사용 가능한 소스 선택 정책과 구분한다.

macOS 기본 두벌식(`2SetKorean`), 세벌식(`3SetKorean`), 세벌식 390(`390Sebulshik`), 공진청 로마자(`GongjinCheongRomaja`), 한컴 로마자(`HNCRomaja`)를 지원한다. 이 ID들은 `com.apple.inputmethod.Korean.` 접두어를 사용한다. 지원하지 않는 한국어 입력기·배열은 두벌식으로 해석한다.

영타는 QWERTY 영문 키 위치로 해석하고 대문자는 Shift 키 위치에 대응한다. 두벌식은 대응 자모를 기존 조합기로 합치며 숫자·문장부호를 유지한다. 세벌식은 macOS에 설치된 자판 자료에서 대응표를 읽고 초성·중성·종성 역할을 보존하여 겹자모와 음절을 조합한다. 숫자·문장부호 위치도 배열에 따라 자모나 다른 기호로 변환한다. 공진청·한컴 로마자는 설치된 Apple 자판 자료의 키 위치와 배열별 모음 결합·자음 조합 규칙을 적용한다. 원래 영문이 나오는 키는 보존한다. 공백·탭·CR·LF는 배열에 관계없이 유지한다. 영어 단어와 고유명사를 추론하지 않는다.

세벌식·로마자 자료가 없거나 구조를 해석할 수 없으면 두벌식으로 변환한다. 시스템 입력 소스를 전환하거나 가상 타이핑으로 대응표를 수집하지 않는다. 요청부터 편집 적용 전까지 입력 소스 ID를 재확인하고, 소스 변경을 관찰하면 대기 변환을 취소한다. 시작 시 소스 조회가 불가능한 경우에도 조회 상태가 유지되면 두벌식 복구를 허용한다. 기본값 적용은 배열 해석에만 해당하며 권한·보안 입력·선택·포커스 등 편집 안전 조건은 유지한다.

### 자모 합치기

호환 자모는 왼쪽부터 조합하고 명시적 초·중·종성 자모 구간에는 NFC를 적용한다. 기존 음절·외국어·문장부호와 조합할 수 없는 자모는 보존한다.

명시적 선택을 우선한다. 선택이 없으면 UTF-16 커서 위치가 속한 문단 전체를 처리하며 실제 줄바꿈 문자는 대상에서 제외한다. 화면의 자동 줄바꿈은 문단 경계가 아니다.

### 한자 후보와 원문 보정

선택한 완성형 한글 또는 커서 바로 앞의 연속된 완성형 한글 범위를 대상으로 한다. AX 선택 반영을 확인한 뒤 Option+Return을 전달하고 후보 표시·선택·취소는 Apple 입력기가 처리한다.

일부 편집기가 원문을 대체하지 않고 한자를 뒤에 추가하면 제한적으로 보정한다. 원문과 같은 음절 수의 한자만 대상 뒤에 추가되고 주변 텍스트·커서·포커스·입력 소스 등 검증 조건이 일치할 때만 한 번 적용한다. 정상 대체 결과와 부분 변환·괄호 병기 등 조건 밖의 결과는 수정하지 않는다. 후보 확정 입력 후 결과를 확인하며 취소·다른 입력·환경 변경 시 감시를 중단한다.

기본 IME 변환과 보정 붙여넣기는 별도 편집이므로 Undo 한 번으로 원문 복원을 보장하지 않는다.

## 첫 자음 조합 보정

첫 자음 조합 보정은 별도 메뉴 설정 없이 기본 동작한다. 진단용 실행 옵션 `--disable-onset-recovery`로 해당 실행에서만 비활성화할 수 있으며 설정으로 저장하지 않는다. 한Q 입력 기능이 활성화되면 시스템의 실제 키보드 포커스 소유 프로세스를 추적하며 앱 이름·경로로 제한하지 않는다. Spotlight처럼 앱을 활성화하지 않는 패널도 같은 절차로 처리한다. 시스템 포커스를 읽지 못한 경우에만 전면 앱의 접근성 포커스로 대체한다. 시스템 포커스가 다른 프로세스를 가리키면 뒤쪽 앱에 남아 있는 입력칸으로 대체하지 않는다. 입력 대상이 바뀌면 이전 입력칸 상태를 폐기하고 대상을 갱신한다. 글자·선택 범위를 읽을 수 없거나 선택을 변경할 수 없는 입력칸, 보안 입력과 배열을 확인할 수 없는 입력기는 편집하지 않는다. Apple 두벌식·세벌식·세벌식 390·공진청 로마자·한컴 로마자를 지원하며 자동 편집에서는 알 수 없는 배열을 두벌식으로 대체하지 않는다.

지원하는 한국어 입력 소스에서 입력창 밖이라는 최근 관측을 바탕으로 첫 자음을 통과시키고, 본문·커서·원래 입력칸을 확인해 예약을 원자적으로 인수한 뒤 후속 키를 보관한다. 확인 전에 이어지는 입력은 편집기에 그대로 전달하며 미확인 입력칸을 위해 키를 보관하지 않는다. 첫 키 후 350ms 이내 입력창의 커서 앞에 해당 자음만 나타났는지 기존 내용과 비교하고, 그 자음만 선택하여 같은 물리 키로 대체한다. 잘라내기와 클립보드는 사용하지 않으며 입력 소스도 전환하지 않는다. 단일 첫 자음 경로에서는 이미 지나간 후속 입력을 추측하여 두 자모 보정으로 처리하지 않는다. 세벌식은 설치된 Apple 자판표의 물리 키 위치와 Shift 배열에서 초성만 읽고 종성 전용 키를 제외한다. 로마자는 실제 키 위치와 Shift 배열의 초성 자음만 대상으로 하고 모음·완성 음절·영문·기호 키를 제외한다. 호환 자모와 명시적 초성 자모 표기는 같은 초성으로 확인하되 원래 물리 키를 재입력한다. 키 보관을 시작한 입력 소스 ID를 기억하고 편집·전달 중 다른 소스로 바뀌면 중단한다. 자판표 읽기는 입력 이벤트 callback 밖에서 수행한다. 조합 밑줄 유무를 판별하지 못하므로 정상 조합 중인 첫 자음도 재입력할 수 있으며, 명시적인 조합 범위를 제공하는 입력칸은 편집하지 않는다.

첫 조회에 기존 본문만 보이거나 해당 자음 한 글자는 반영됐지만 커서가 이전 위치인 경우, 첫 키 시점부터 최대 300ms 동안 같은 입력칸의 글자·커서를 재확인한다. 기존 350ms 예약 기한은 연장하지 않으며 자음과 커서가 확인되면 즉시 보정한다. 재확인 중 입력칸·본문·선택·입력 소스가 바뀌면 중단하고 미전달 키를 보존한다. 기한 내 반영되지 않거나 처음부터 후보가 정확히 일치하지 않는 경우에는 글자 선택·대체를 생략하고 같은 입력칸에 보관한 후속 키를 순서대로 전달한다. 기한 이후의 반영이나 보정 대상 밖 입력까지 정상 조합을 보장하지 않는다.

예상 문자열·커서 위치·선택 해제와 재입력 이벤트의 게이트 통과를 확인한 뒤 보관한 후속 키를 순서대로 전달한다. 전송 조건을 만족하지 못한 이벤트는 완료로 세지 않고 미전달 목록에 보존한다. 전송 API 호출은 대상 앱의 입력 처리를 보증하지 않는다. 별도 입력 게이트는 첫 키 예약 350ms, 보정 최대 800ms, 관측 지연 250ms, 보관 128개 제한을 적용한다. 권한·보안 입력·포커스·소스 변경이나 탭 중단 시 입력 차단을 해제한다. 권한·보안 입력·한Q 수명 조건이 충족되면 새 감시 장치를 생성해 새 입력부터 자동 재시작한다. 실패 시 1·2·4·8초 간격으로 재시도하며 횟수 제한으로 영구 중단하지 않는다. 미전달 키는 메모리에만 보존하고 사용자 복사 메뉴나 클립보드 전송은 제공하지 않는다. 앱 종료 후에는 보존하지 않는다. 한자·수동 자모 편집과 동시에 시작하지 않으며 한Q가 생성한 합성 키는 첫 자음 감지 대상에서 제외한다.

첫 키 예약 후 초기 조회가 일시적으로 실패하면 기존 150ms 재확인 시간을 유지한다. 이후에도 조회되지 않으면 예약을 해제한다. 본문 편집·재전송을 시작하지 않았고 보관 입력·미확인 전송이 없으면 안정화 대기 없이 새 관측을 계속한다. 미전달 입력이 있거나 편집을 시작한 경우에는 기존 보존·안정화 대기를 유지한다. 편집 전 빈 예약의 관측 지연·기한 만료도 감시 장치를 종료하지 않으며, 메인 처리기가 미전달 입력을 확인하기 전에는 새 예약을 허용하지 않는다. 처음 통과시킨 키의 놓음은 다른 키를 보관하거나 편집을 시작하기 전이라면 즉시 통과시킨다. 역할 조회 실패를 입력창 밖이라는 확인으로 사용하지 않는다. 권한·보안 입력·전면 앱·입력 소스 변경과 수동 편집 충돌은 기존 안전 중단을 유지한다. 이 대기는 최초 지연 입력의 보정을 보장하지 않으며 이전 미전달 키를 자동 재전송하지 않는다.

보정 도중 일시적인 입력칸 조회 실패는 현재 보정을 취소하고 일반 입력을 통과시키는 대기 상태로 전환한다. 지원하는 한국어 입력 소스의 같은 입력칸과 선택 없는 커서를 100ms 이상 확인하고 이미 전송한 이벤트의 게이트 통과를 확인하면 새 입력부터 자동 재개한다. 통과 확인 개수가 부족한 상태를 관측한 뒤 250ms 이상 지속되면 입력칸 조회·소스 상태와 무관하게 현재 감시를 종료하고 기존 재시작 절차를 따른다. 일부 확인만 도착해도 대기 기한을 연장하지 않는다. 보관 키 전달 후 마지막 통과 확인 대기에도 같은 제한을 적용한다. 이전 미전달 키는 메모리에 별도로 보관하며 이미 전송한 키와 함께 자동 재전송하지 않는다. 이전 보정의 예약 작업은 무효화하고 감시 구간별 식별표를 사용하여 이전 구간의 늦은 이벤트를 새 통과 확인으로 세거나 입력 큐에 다시 넣지 않는다. 이미 OS에 보낸 이벤트를 취소하거나 대상 앱 수신을 보증하는 기능은 아니다. 권한 철회·이벤트 탭 장애는 상태 복구 후 새 감시 장치로 재시작하며, 진단용 비활성화·한Q 종료와 업데이트 정책 제한은 존중한다.

입력 문자열·키 값·클립보드를 로그에 저장하지 않는다. 자동 검사는 실제 앱·물리 키 검증을 대신하지 않는다.

### 지연·재진입 입력의 제한적 보정

첫 자음과 놓음만 통과한 뒤 본문 공개가 늦어진 경우에는 첫 키부터 2초 이내에 원래 키·본문·커서·입력 소스를 다시 확인한다. 후속 입력이 이미 통과하면 이 단일 키 경로를 인수하지 않는다. 초기 예약의 350ms 기한이나 보관 입력의 기한을 연장하지 않는다.

두벌식에서는 이미 통과한 입력을 첫 키부터 2초·최대 16키 범위로 관측한다. 관측 자체는 키를 보관하거나 재전송하지 않는다. 입력창 밖이라는 관측이 첫 키보다 늦은 빠른 재진입도 최근 확인한 원래 입력칸·본문·커서의 발행 기준으로 연결한다. 해당 기준과 실제 입력칸·입력 소스·주변 본문·관측한 전체 키의 분리 결과·UTF-16 커서가 모두 일치해야 한다. 모든 키가 놓이고 마지막 키가 Shift 없는 Space여야 하며 정상 조합·추가 키 경합·클릭·단축키·기한 초과는 보정하지 않는다.

조건이 맞는 확정 입력은 원래 AX 요소의 선택 텍스트로 한 번만 치환한다. 여러 키를 현재 초점에 재전송하지 않으며 텍스트 쓰기를 지원하지 않는 입력칸에는 선택·본문 변경을 하지 않는다. AX 요청 결과가 불확실해도 같은 편집을 재시도하지 않고 원래 요소의 본문·커서로 적용 여부를 확인한다. 이후 보관한 원래 키의 전달에는 기존 대상·입력 소스 확인을 적용한다. 입력 소스나 클립보드를 변경하지 않는다.

전송 확인은 키마다 발행 시각을 기록해 가장 오래된 미확인 전송부터 250ms 기한을 적용한다. 정상적으로 확인된 이전 키의 대기 시간을 다음 키에 이어 붙이거나 새 키로 오래된 기한을 연장하지 않는다. 재전송 중 일시적 본문·선택 조회 실패는 기존 보관 기한 안에서만 다시 확인하고 실제 대상·입력 소스 변경에는 전달하지 않는다. 접두부 반영이 확인되고 남은 키가 없으면 현재 초점 조회 없이 전송 확인과 완료를 처리하되, 메인 큐에서 대기 입력을 다시 수집한 뒤 종료한다. 게이트 통과는 대상 편집기의 모든 입력 처리 보증이 아니다.

일시 중단 뒤 전송 확인이 끝나고 미전달·보관·잔여 접두부가 없을 때만 이전 재전송 상태를 정리한다. 원래 입력칸의 기준은 같은 입력 소스와 본문·커서를 읽어 갱신하며 다른 입력칸을 편집할 권한으로 사용하지 않는다. 진단은 명시적 실행 옵션을 켰을 때 고정 단계·사유·시각·개수만 기록한다. 입력 게이트 안에서는 최대 256개 진단 프레임만 메모리에 쌓고 파일 출력은 잠금 밖에서 수행하며 입력 내용·키 값·대상 식별자를 기록하지 않는다.

## 입력과 편집의 안전 조건

일반 키의 최초 HID 관측은 AX 조회와 메인 RunLoop를 사용하지 않는 별도 입력 탭에서 수행한다. OS가 지정한 대상 PID가 당시 활성 앱과 일치하고 기존 식별표가 없는 누름·놓음에 한해 일회용 식별자를 붙인다. 최대 1,024개·2초 범위에서 관리하며 Quartz가 이벤트 시각을 다시 지정하더라도 원래 대상과 키 종류·출처를 대조한다. 주 입력 처리 전과 일반 통과 직전에 활성 앱이 바뀌었으면 원래 이벤트를 원래 프로세스에 한 번 보내고 일반 반환 경로에서는 소비한다. 본문·선택·입력 소스·포커스는 변경하지 않는다. 비활성 패널의 대상 PID가 활성 앱과 다르면 기존 처리 경로를 유지한다. 권한·보안 입력·수명 해제 조건은 전달 직전에 확인한다. 이 처리는 이미 보정기가 보관하거나 재입력한 이벤트의 복귀를 승인하지 않는다. 지연된 확정 입력의 보정은 위 정확 일치 조건을 적용하며, 미전달 입력을 다른 앱에 보내는 근거로 사용하지 않는다.

- 전용 키로 소비하기 시작한 우측 modifier의 상태를 키를 놓을 때까지 관리하고 좌측 modifier는 보존한다. 한자키는 Command·Control·Shift 조합 상태에서 새 요청을 받지 않는다.
- 앱이 합성한 이벤트는 식별해 재처리하지 않는다. 보안 입력 중에는 새 키 매핑·텍스트 변환 요청을 처리하지 않는다.
- AX 범위는 UTF-16 기준이다. 비동기 편집 단계마다 권한, 보안 입력, 포커스, 텍스트, 선택, 입력 revision을 재확인한다.
- 접근성 읽기에 짧은 타임아웃을 적용한다. Chromium/Electron 접근성 준비를 요청하더라도 재시도는 제한하고 입력 상태를 재확인한다.
- 확인 가능한 IME 조합 중 텍스트와 보안 텍스트 필드는 편집하지 않는다. `AXMarkedTextRange`를 제공하지 않는 편집기의 조합 상태는 별도 호환성 검증이 필요하다.
- 붙여넣기를 통해 대상 편집기의 Undo 경로를 사용한다. 클립보드는 편집 반영 후 복원하며 사용자가 새로 복사한 값은 덮어쓰지 않는다.

## 메뉴바·설정·HUD

앱 표시 이름은 한Q, 실행 파일과 번들 이름은 HanQ, 번들 ID는 `taek.in.hanq`다. `LSUIElement=true`인 메뉴바 앱으로 실행하며 일반 실행에서는 권한이 없을 때 권한 안내 창을 표시하고, 미설정 외부 키보드가 감지되면 키 확인 창을 표시한다.

한Q 한영 전환은 관측한 앞선 문자와 선택이 같은 입력칸에 반영됐는지 확인한 뒤 진행한다. 확인 중 뒤따른 키와 추가 전환 요청은 순서대로 보관하며, 이미 전달한 누름의 놓음은 지연시키지 않는다. 첫 자음·불일치 보정 중에는 해당 처리도 기다린다. 보정 대기 동안 중복 AX 조회를 하지 않으며, 최대 3초의 보정 대기 뒤 자체 편집기 확인 기한 1초를 새로 적용한다. 보정 대기 자체가 기한을 넘으면 미전달 키를 보관한다. 본문·선택을 읽을 수 있는 입력칸에서 자판별 예상 결과를 비교하며, 관측한 입력 구간 안의 ASCII 대소문자 변환만 허용한다. 전환 직후 늦게 적용된 대문자화를 구분할 수 있도록 검증한 삽입 이력은 유지하며, 소스 전환 경계에서는 새 키 입력 없이도 이전 한글 조합을 끊는다. 주변 본문·문자 수·선택은 그대로 확인하고 앱의 대문자화를 되돌리지 않는다. 처음부터 확인할 수 없는 입력칸은 기존 전환 경로를 유지한다. 일시 조회 실패는 기존 기한 안에서 재확인하고 실제 포커스 변경·기한 초과·대기열 한도 도달 시 미전달 키를 보관한다. 불일치 보정이 본문과 커서까지 검증한 입력 이력을 넘겨받아 진행 중인 한글 조합을 이어서 추적한다. 앞쪽 처리기가 보정 중에 본 키는 뒤쪽 보정 처리기의 실제 전달 여부를 확인하며, 보정 완료 경계를 넘어 전달된 키만 검증 이력에 한 번 이어 붙인다. 보정기가 보관한 키는 중복 반영하지 않는다. AX 값 없음 응답은 별도 문자 수 조회가 0일 때만 빈 본문으로 인정하며 시간 초과·지원하지 않는 속성은 빈 본문으로 대체하지 않는다. 명시적인 전체 선택은 앞선 본문을 확인한 뒤 적용 여부를 확인한다. Apple 한국어 입력기가 활성화된 비어 있지 않은 본문에서는 소스를 바꾸지 않고 오른쪽 방향키 누름·놓음과 Command-A 누름·놓음을 순서대로 보내 조합을 확정하고 전체 선택을 다시 적용한다. 같은 입력칸·본문·선택의 재확인 후 후속 편집 키를 전달한다. 대기열의 일반 키를 전달할 때는 입력칸의 동일성을 확인하고, 전환·전체 선택·마지막 결과에서는 본문과 커서를 검증한다. 전송한 키가 주 입력 처리기에 도착하기 전에는 중복 AX 조회를 하지 않는다. 한영 전환 뒤에도 검증한 본문과 선택을 유지하며, 선택 복원 요청의 성공만으로 후속 키를 전달하지 않고 실제 반영을 기다린다. 같은 입력칸과 같은 본문에서 선택 변경 응답만 성공하고 실제 선택이 미반영된 경우 10ms 이상 간격으로 두 번까지 재시도하며, 실제 선택 확인 전에는 후속 키를 전달하지 않는다. 이미 OS에 전달한 키는 취소하지 못한다. 입력 문자열을 로그에 남기지 않는다.

전환·전달이 진행 중이지 않을 때 새 문자·전체 선택·한영 전환 요청의 포커스 요소가 이전 관측 입력칸과 다르면 이전 관측 이력을 폐기하고 새 입력칸의 본문·선택으로 시작한다. 새 입력칸에 이미 제출한 문자는 해당 입력칸의 예측 이력으로 반영을 기다린다. 포커스 조회 실패를 입력칸 변경으로 간주하지 않으며 같은 입력칸의 예상 밖 본문·선택을 새 기준으로 덮어쓰지 않는다. 진행 중인 전환·전달의 원래 입력칸은 바꾸지 않고 실제 대상 변경 시 미전달 키를 보관한다.

한영키 사용·한자키 사용·HUD 표시 설정은 각각 저장하고 최초 기본값은 ON이다. 로그인 자동 실행은 `SMAppService.mainApp`으로 등록하며 이후 사용자 선택을 존중한다. 시스템 Caps Lock 전환 설정은 최초 실행에도 기존 값을 유지한다.

HUD는 실제 선택된 입력 소스의 시스템 표시 이름을 한 줄로 표시한다. 앱의 전환키뿐 아니라 시스템 단축키와 입력 메뉴의 변경도 관찰한다. 초기 상태와 중복 알림으로 불필요하게 표시하지 않으며, 이름을 읽지 못하면 표시하지 않는다. 포커스를 가져오지 않고 클릭을 통과시키며 긴 이름은 말줄임 처리한다. HUD는 모든 입력기의 입력 준비 완료를 보장하는 표시가 아니다.

정보 창은 번들의 베타 식별자를 포함한 버전·빌드 번호·저작권과 라이선스를 제공한다. 업데이트 확인과 자동 확인 설정은 주 UI 인스턴스의 Sparkle updater에 연결한다. 검사·재실행 helper에서는 updater를 시작하지 않는다.

실행·업데이트 확인 시 서명된 필수 정책을 비동기로 조회한다. 적용 대상의 최소 허용 빌드 미만이고 공개 설치 파일이 조회되면 기존 입력 해제 경로로 기능을 중단한다. 권한 타이머와 메뉴는 제한을 우회해 감지를 재개하지 않는다. 설정값은 보존하며 정책 조회 실패·만료·철회 시 권한과 키 상태를 재확인한 뒤 복귀한다. 상세 적용 조건은 [필수 업데이트 정책](RELEASE.md#필수-업데이트-정책)을 따른다.

## Roman Switch 직접 제어 — 현재 구현 계약

Caps Lock 전환 설정은 `RomanSwitchController.swift`에 격리한 비공개 HIToolbox API로 제어한다. 시스템 전체 설정이므로 앱 종료나 한영키 사용 설정이 OFF일 때 자동 복원하지 않는다. Caps Lock 대문자 잠금 기능을 가로채지 않는다.

런타임 로딩 대상은 다음 경로다.

```text
/System/Library/Frameworks/Carbon.framework/Versions/A/Frameworks/HIToolbox.framework/Versions/A/HIToolbox
```

| 진입점 | 계약 |
| --- | --- |
| `isSupported` | 프레임워크와 필수 심볼 로딩 성공 여부. 미래 OS의 ABI 호환성을 보증하지 않음 |
| `isEnabled()` | `TISIsRomanSwitchEnabled`의 nonzero 반환값으로 실제 활성 상태 판정. ABI는 `@convention(c) () -> Int32` |
| `setEnabled(_:)` | `TISSetRomanSwitchState`에 ON=1, OFF=0 전달 후 getter로 검증. ABI는 `@convention(c) (Int32) -> Void` |

`dlopen`/`dlsym`으로 로딩하고 정적 `Result`에 성공·실패를 보관한다. 함수 포인터를 사용하는 동안 handle을 유지하며 심볼 로딩 실패와 Runtime 해제 시 닫는다. 프레임워크 부재, 심볼 부재, 설정 후 불일치를 오류로 구분한다. raw preference나 `TISGetRomanSwitchState`로 활성 상태 판정을 대신하지 않는다.

메뉴는 ON이면 체크, OFF이면 해제, 조회 실패이면 mixed·비활성이다. 한영키 사용 설정이 ON이고 API 지원·조회 성공을 모두 만족해야 조작할 수 있다. 변경 실패는 경고창으로 안내한다. 설정 UI 자동화, `defaults` 쓰기, 프로세스 재시작으로 API 제어를 대체하지 않는다. 경로·심볼·ABI 정의는 컨트롤러 밖에 복제하지 않는다.

## 권한과 프로세스 수명

UI 인스턴스만 프로세스 수명 동안 파일 잠금을 보유해 중복 실행을 막는다. 검사·재실행용 인스턴스는 UI 잠금을 획득하거나 이벤트 탭을 만들지 않는다.

권한 없는 앱은 입력을 가로채지 않고 안내 창을 표시한다. 허용되면 저장된 설정으로 감지를 시작한다. 시스템이 이벤트 탭을 중단하면 탭·런루프 소스·키 상태·대기 작업을 정리하며 무조건 자동 재활성화하지 않는다.

기존 프로세스가 권한 철회를 늦게 인식할 수 있어, 탭이 있는 동안 `FreshPermissionMonitor`가 동일 번들의 새 LaunchServices 인스턴스로 권한을 확인한다. 권한 거부·검사 오류·시간 초과에는 본체를 종료한다. 메인 루프의 응답 중단은 별도 watchdog으로 감시한다. 시스템 설정 앱도 같은 안전 정책을 적용한다.

확인된 권한 거부에 한해 준비된 helper가 본체 종료 후 같은 앱을 한 번 재실행한다. 메뉴 종료, 검사 오류, watchdog 종료는 재실행하지 않는다. 재실행된 앱은 권한 없음→허용 전환을 관찰하기 전까지 추가 자동 재실행을 제한한다. helper 통신의 단순 EOF를 재실행 신호로 취급하지 않는다.

## 개인정보와 진단

사용자 입력 문자열·클립보드 내용·비밀번호를 로그나 진단 자료에 저장하지 않는다. 진단 모드는 명시적으로 켰을 때 처리 단계와 숫자 상태를 수집한다.

피드백은 기본 브라우저에서 폼을 열고 앱 버전·빌드 번호, macOS 버전, Mac 모델 ID를 미리 채운다. 사용자가 수정하고 직접 제출한다. 일련번호·하드웨어 UUID는 포함하지 않으며 모델 조회 실패 시 해당 필드는 비운다.

## 배포와 호환성

로컬 산출물은 `build/HanQ.app`이다. 빌드 스크립트는 macOS 13.0을 최소 대상으로 설정하고 arm64로 컴파일한다. 별도 후보는 `--candidate`로 `build/candidate/HanQ.app`에 생성한다. 현재 제공 대상은 Apple Silicon이며 Intel용 범용 바이너리는 포함하지 않는다.

공개 0.2.0은 ad-hoc 서명이며 미배포 0.3.0 후보에는 동일 자체 서명 인증서를 적용했다. Developer ID 서명·공증은 미적용이다. 후속 후보와 배포 준비에는 같은 인증서 지문을 명시하며, 요청한 인증서로 서명하지 못하면 실패한다. 인증서 인수·환경변수를 생략하면 기본 로컬 빌드는 ad-hoc이다. 동일 인증서의 권한 유지 검증 범위와 남은 조건은 [개발 안내](DEVELOPMENT.md#새-빌드-테스트-전-손쉬운-사용-권한-사전-체크)를 따른다. 자체 서명 후보의 검증을 공개본·모든 환경의 권한 유지 보장으로 확대하지 않는다. 업데이트 조회·정책 제한을 연결했다. 실제 앱의 다운로드·교체·재실행·설정 보존을 확인했으며, 기존 ad-hoc 서명은 빌드별 코드 해시를 식별 조건으로 사용한다. 검증 환경에서 이전 빌드에 저장된 손쉬운 사용 권한 조건을 새 빌드가 충족하지 못함을 확인했으며, 업데이트 시 권한 유지를 보장하지 않는다. 최소 배포 대상 설정과 자동 검사 성공만으로 모든 macOS·편집기·키보드에서의 동작을 보장하지 않는다. 지원 환경 안내와 공개 범위는 실제 검증 수준에 맞춰 유지한다.

## 한국어 입력 소스 불일치 복구

한Q 입력 기능과 함께 자동으로 동작한다. Apple 기본 한국어 입력기 다섯 종류(두벌식·세벌식·세벌식 390·공진청 로마자·한컴 로마자)에서 감지하며 입력 소스가 유지되는 도중의 영문도 대상이다. 모든 앱에 같은 접근성 확인 절차를 적용하며 첫 자음 보정과 동일한 실제 키보드 포커스 선택 정책을 사용한다. 동기·비동기 본문 조회 전후에 포커스가 같은 입력칸인지 재확인한다. 실제 본문·선택 범위와 관측한 키가 일치하고 선택 변경이 가능한 경우에만 편집한다. 보안 입력·권한 부재·다른 앱이나 입력칸·변경된 본문은 편집하지 않는다.

### 입력 이력과 전환 경계

수신한 키 이벤트의 키 위치·Shift 상태와 실제 삽입된 문자를 비교한다. 전환 대기열에 들어간 요청은 앞선 입력의 보정 후보와 시각 경계를 유지한다. 본문 확인과 실제 입력 소스 전환이 성공한 뒤 요청 시각을 경계로 기록하고 이전 감지 후보를 정리한다. 대기 없이 직접 전환하는 경로와 복구 중 사용자 의도 기록은 기존 경계 처리를 유지한다. 이미 완료된 한Q 전환 요청보다 이전 시각에 발생한 키가 뒤늦게 관측되면 새 언어의 보정 후보에 포함하지 않는다. 복구 중 보관한 키는 최초 HID 입력 단계에서 사용자 전환과 같은 순서로 기록한 언어 의도에 배정한다. 뒤쪽 처리기에서 이벤트 시각이 바뀌어도 이 분류를 유지한다. 임시 식별자는 최대 1,024개까지 관리하고 처리 뒤 제거하며, 이력이 없는 이벤트는 기존 발생 시각 기준을 사용한다.

### 선택 대체와 자동 완성

명시적 선택을 대체하는 첫 키도 선택 범위를 제거한 기준 본문과 비교한다. 주소창 자동 완성의 선택 부분을 제외한 결과가 이전에 관측한 모든 ASCII 키·주변 본문·커서와 정확히 일치하면 기존 키 이력을 유지한다. 이미 확인한 같은 자동 완성 본문·선택이 늦게 갱신되는 동안에도 후속 관측 키를 보존한다. 새로 바뀐 선택, 입력한 접두부의 전체·일부 선택, 기존 본문 선택에는 이 예외를 적용하지 않는다. 자동 완성 문자는 재입력하지 않으며 실제 편집 전에는 관측한 전체 키에 대한 본문 검증을 유지한다.

### 혼합 입력과 분리 자모

전환 경계에서 영문 접두부 뒤에 한글이 붙은 경우는 최대 64개 관측 키의 영문 구간과 해당 한국어 배열의 조합 결과가 삽입 전체·주변 본문·커서에 정확히 일치할 때만 복구한다. 정상 한글과 배열에서 원래 나오는 영문·숫자 접두부는 혼합 오류로 취급하지 않는다. 일부 키만 AX에 반영된 경우 추적을 유지하되 전체 입력이 확인되기 전에는 혼합 구간을 편집하지 않는다. 두벌식에서는 관측한 최대 64개 키의 정상 한글 접두부도 유지한다. 삽입 전체가 각 키의 분리된 자모 출력과 정확히 일치하고 정상 조합 결과와 다르며 주변 본문·커서가 그대로일 때만 같은 복구 절차를 적용한다. 정상 자음 단독 입력·명시적 공백·관측하지 않은 기존 자모와 다른 배열에는 이 감지를 적용하지 않는다.

### 복구와 후속 입력 순서

숫자·공백·기호를 포함한 연속 입력을 추적하고, 불일치 구간을 선택한 뒤 소스를 영어와 해당 구간의 원래 한국어 입력 소스 ID로 재지정하여 재입력한다. 시스템의 활성화된 Control-Space 전환을 사용한다. 합성 누름·놓음은 같은 독립 키 상태를 공유하며, modifier 적용·해제와 입력기 활성화가 다음 전환을 앞지르지 않도록 단계 사이를 기다린다. 복구 전에 편집기에 전달된 키의 놓음을 복구 대기열에 지연시키지 않는다. 복구 중 사용자 한영 전환은 임시 소스가 아닌 사용자 의도에 누적한다. 복구 도중 전체 선택(Command-A)은 보정이 본문·커서를 검증할 때까지 후속 키와 함께 전환 대기열에 보관한다. 검증된 입력칸·이력을 넘겨받은 뒤 일반 전체 선택 경로에서 삭제·전환·대체 입력을 순서대로 처리한다. 대기 중 오른쪽 Command도 같은 순서로 처리하며 보정 중 임시 소스 전환으로 먼저 소비하지 않는다. 보정이 검증 없이 끝나면 보관한 편집 키를 추측 전달하지 않는다.

### 편집 검증과 제한적 재시도

선택 적용 전 원문과 적용 후 선택 범위를 재확인한다. 선택 직전·직후 앱이 새 ASCII 구간의 대소문자만 바꾸면 실제 표기를 다시 기록하고 원래 물리 키로 복구한다. 주변 본문·문자 수·다른 문자 변경은 허용하지 않으며, 이미 한글이 섞인 검증 구간에는 이 예외를 적용하지 않는다. 같은 입력칸과 검증된 본문에서 선택 요청만 성공하고 실제 선택이 풀린 경우 기존 확인 기한 안에서 두 번까지 다시 적용하며, 실제 선택과 선택 문자열 확인 전에는 대체 키를 보내지 않는다. 이 단축키를 사용할 수 없으면 이번 복구를 중단하고, 요청 후 전환이 지연되면 초기 복구와 후속 키 전달 단계 모두 정확한 소스 ID 선택을 추가 시도한다. 전환 확인 뒤 늦은 소스 변경이 도착하면 편집 직전 단계에서도 알고 있는 목표 소스를 재선택하고 본문·선택을 다시 검증한다. 전환 확인 뒤 되돌아간 소스의 복원은 한 번의 복구에서 최대 2회와 기존 진행 기한으로 제한한다. 입력 소스 표시만으로 성공을 판정하지 않으며 실제 결과와 커서·후속 묶음을 확인한다.

### 배열 유지와 안전 중단

복구 후보부터 재시도·결과 확인까지 원래 배열을 유지한다. 세벌식은 숫자 위치의 자모와 Shift 배열, 초성·중성·종성 역할을 반영한다. 공진청·한컴 로마자는 각 배열의 모음 결합과 자음 조합 규칙을 구분한다. 해당 배열에서 정상 영문이 나오는 키는 불일치로 취급하지 않는다. 자판 배열을 확인할 수 없는 입력기는 자동 복구하지 않는다. 자판 자료 로딩은 수동 선택 영타 변환·첫 자음 보정과 공유하고, 로마자 조합 규칙은 선택 영타 변환과 공유한다. 모든 기능의 제품 지원 대상은 위 한국어 입력기 지원 정책을 따른다.

복구 중에는 후속 키를 보관하고 원래 입력 소스 구간에 따라 전달한다. 한Q 우측 Command와 등록된 외부 한영키 전환은 전달 전후의 소스 경계로 보관한다. Caps Lock·메뉴바 전환의 구간 추적은 아직 지원하지 않는다. 보정 중이 아닌 일반 영어 입력에서는 한국어 보정용 본문 조회를 생략하고 이전 감지 후보를 버린다. 한국어로 전환하면 새 본문 관측을 재개한다. 복구 조회는 별도 큐에서 수행하며 오래된 응답은 작업 세대·포커스로 배제한다. 진행이 확인될 때만 2.5초 대기 한도를 갱신한다. 전송 호출 자체는 성공으로 세지 않는다.

첫 자음 보정·수동 자모/한자 편집과 복구는 동시에 실행하지 않는다. 한Q 합성 키는 감지에서 제외한다. 복구 실패로 남은 키는 메모리에만 보존하고 새 감지를 중지한다. 보관된 입력을 복사하면 해당 키의 영문 표기를 클립보드에 넣고 보관 목록을 비운 뒤 감지를 재개한다. 보관된 키 없이 중단된 경우 한Q를 다시 실행하여 재개한다. 다른 입력칸에 자동으로 재전송하지 않는다. 정상 복구는 클립보드를 사용하지 않고 명시적 복사 메뉴만 클립보드를 변경한다. 입력 문자열·키 값·클립보드는 진단에도 기록하지 않는다.

알려진 제한으로 Safari에서는 자모 분리가 발생할 수 있고, VS Code 기본 편집기에서는 본문 조회가 제한되어 복구하지 못할 수 있다.
