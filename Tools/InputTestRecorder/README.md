# ChatGPT 입력 시험 도구

## 자동 입력 시험 앱

사용자가 직접 실행하고 시작하면 현재 대화용 ChatGPT 앱(`com.openai.codex`)의 빈 입력창에서 실제 물리 키 위치에 해당하는 합성 키를 입력하고 AX 본문·커서를 대조한다. Classic은 대상이 아니다. 이 도구의 직접 실행은 사용자가 수행한다.

```sh
bash scripts/build-chatgpt-input-test.sh
open 'build/chatgpt-input-test/HanQ ChatGPT Input Test.app'
```

기존 산출물은 덮어쓰지 않는다. 출력 폴더는 첫 인자로 바꿀 수 있고 로컬 서명은 `HANQ_SIGNING_IDENTITY`로 선택한다. 기본은 ad-hoc 서명이다. 한Q 본체와 별개 앱이므로 도구 자체의 손쉬운 사용·키 전송 권한이 필요하다. ‘권한 설정’ 버튼에서 사용자가 직접 허용한다. 한Q 본체의 권한을 초기화하거나 설정을 바꾸지 않는다.

1. 진단 모드의 한Q를 켜 둔 상태에서 현재 ChatGPT의 빈 초안과 두벌식을 준비한다.
2. ‘자동 시험 시작’을 누르고8초 안에 그 빈 입력창을 클릭한다.
3. 실행 중에는 키보드·마우스를 사용하지 않는다. Escape·사용자 입력·포커스/입력칸 변경·한Q 종료에는 중단한다. 한Q 복구의 임시 소스 전환은 결과 확인 기한 안에서 복원을 기다리며 원래 두벌식이 돌아오지 않으면 별도로 실패한다.
4. 종료 후 ‘결과 폴더’에서 로그를 확인한다. 마지막 시험 문장이나 첫 실패 초안은 그대로 남으므로 확인 후 직접 지운다. 메시지를 전송하는 Return/Enter는 보내지 않는다.

기본 시험은 총100회 문장 입력이며 약3분 걸린다. 다섯 고정 문장을 각각20회 입력하고 명목40/20/8ms 조건은 각각35/35/30회다. 첫30조건의 순서·문장은 이전 도구와 같다. 초기 빈 초안1회, 선택 덮어쓰기50회, 지운 뒤 재입력49회로 검사한다.45ms 누름 수명을 사용해 누름·놓음을 겹치며, 같은 키를 다시 누르기 전에는 해제한다. 시험 앱이 직전 회차에서 정확히 확인한 자기 문장만 전체 선택해 지우거나 덮어쓴다. 기존 초안이 있거나 선택 범위를 확인하지 못하면 새 입력·삭제를 시작하지 않는다. 첫 본문/커서 불일치에서 중단하고 결과를 저장한다. 전송 API 성공만으로 통과시키지 않는다.

실제 키 간격도 저장한다. 속도 예산은 실제 누름 간격의95백분위가 `명목 간격×2+4ms` 이하인지로 판정하며, 명목 간격과 정확히 같다는 뜻은 아니다. AX 확인이나 스케줄링 때문에 이 예산을 넘으면 본문 일치와 별도로 `pacingQualified=false`를 표시한다. 속도 미충족 회차를 빠른 입력 검증 통과로 세지 않는다. 현재 도구의 범위는 두벌식·빈 초안 시작·자체 문장 이어 시험/선택 대체이며 모든 앱·배열·자연 지연을 포괄하지 않는다.

기본 결과 위치는 `~/Library/Application Support/HanQ Input Test Recorder/Automatic/session-…/`다.

- `auto-run.json`·`auto-target.json`:100회 계획·예상 문장/키 수/편집 방식, 도구 빌드, 실제 결합한 대상 PID/번들. `session.json`에는 실행 중인 한Q 버전·빌드도 저장한다.
- `auto-attempt-*.json`: 시작한 조건과 고정 합성 문장, 명목 간격·시각.
- `auto-case-*.json`: 본문/커서 일치, 실제 간격, 누락된 예상 UTF-16 위치와 예상 밖 길이, 전송 누름/놓음 개수. 실제 본문·본문 해시·클립보드는 저장하지 않는다.
- `auto-interruption.json`: 도중 중단한 조건·전송 개수·사유.
- `auto-result.json`: 완료/중단 사유, 실제 결과 회차 수, 일치·속도 미충족 수. AX 오류는 속성 이름·오류 코드만 남기고 값은 남기지 않는다.
- 기존 `session.json`·`result.json`·`incidents/`: 한Q 진단 수집 상태다. 이 진단 자체의 수신 미확인 표시와 자동 시험의 별도 AX 대조 결과를 구분한다.

```sh
python3 scripts/summarize-input-test-session.py '<자동 시험 세션 폴더>'
bash scripts/test-chatgpt-input-test.sh
bash scripts/test-auto-input-native.sh '<새 결과 JSON 경로>'
```

검사 스크립트는 대역·소유 네이티브 입력창만 사용한다. 직접 ChatGPT 시험과 합산하지 않는다. 앱의 `--self-test` 모드는 UI 확인 전용이며 시작 버튼을 눌러도 실제 앱 제어를 거부한다. 사용자는 옵션 없이 정상 실행해야 한다. 한Q 진단 수동·자동 구간 한도는 아래와 동일하며, 실패 시 기존 한Q 메뉴의 ‘방금 입력 누락 기록’으로 추가 자료를 남길 수 있다.

요약기는 이전30회 로그도 계속 읽는다.100회 계획과 결과의 ID·예상 문장·속도·편집 방식·예상 누름 수를 대조하고 본문/커서·최종 소스·누름/놓음 균형·누락/추가 위치·속도 미충족을 각각 보고한다. 중도 종료나 일부 결과만 남은 실행을100회 통과로 표시하지 않는다. `input_regression_checks_passed`는 이 입력·삭제·덮어쓰기 범위의 검사다. 한영 전환·한자·HUD·다른 배열과 사람의 물리 키는 별도 회귀 검사가 필요하다. 진단 파일이 없으면 내부 보정 발동 여부는 확인되지 않은 상태로 남는다.

## 수동 입력 진단 기록 앱

사용자가 현재 대화용 ChatGPT 앱에서 직접 입력하는 동안, 한Q의 기존 입력 처리 진단과 관찰 시각을 로컬에 모은다. ChatGPT를 조작하거나 입력·전송·본문 조회를 수행하지 않는다. 한Q 본체를 교체하거나 재실행하지 않으며 별도 손쉬운 사용·키 전송 권한도 요청하지 않는다.

### 준비

한Q는 개발 안내의 권한 사전 체크를 마치고 `--diagnose-input-incidents <전용 폴더>`로 실행 중이어야 한다. 실행 중인 한Q가 하나이고 사용자 전용 진단 폴더에 연결할 수 있어야 기록 시작이 활성화된다. 앱은 한Q의 프로세스 인자에서 해당 폴더를 찾는다. 한Q 실행 파일·Documents의 소스 파일을 읽지 않는다.

```sh
bash scripts/build-input-test-recorder.sh
open 'build/input-test-recorder/HanQ Input Test Recorder.app'
```

빌드 스크립트는 기존 산출물을 덮어쓰지 않는다. 다른 출력 경로는 첫 인자로 지정한다. 로컬 ad-hoc 서명 도구이며 배포용 서명·공증 앱은 아니다.

### 사용

1. 앱의 연결 상태를 확인하고 ‘기록 시작’을 누른다.
2. ChatGPT로 직접 이동해 평소처럼 입력한다. 필요하면 재진입·이어 쓰기·덮어쓰기·전환 구분을 선택한다. 같은 문구를 반복할 필요는 없다.
3. 누락을 발견하면 한Q 메뉴의 ‘방금 입력 누락 기록’을 눌러 직전 처리 상태를 저장한다. 이 앱의 ‘누락 관찰’은 관찰 시각만 남기므로 해당 메뉴의 버퍼 저장을 대신하지 않는다. ‘정상 관찰’도 사용자의 관찰 표시다.
4. ‘기록 종료’를 누르고 저장 완료를 확인한다. 마지막 약 2초의 파일도 수집한다. ‘기록 폴더’에서 결과를 찾는다.

기본 저장 위치는 `~/Library/Application Support/HanQ Input Test Recorder/Sessions/`이다. 폴더를 그대로 보관해 나중에 분석할 수 있다. 외부 전송·업로드 기능은 없다.

### 기록과 제한

- `session.json`: 시작 시각·uptime·고정 시험 대상·한Q PID/실행 경로/시작 시각·본문/키/클립보드 미수집 여부.
- `event-*.json`: 구간 선택, 사용자 정상/누락 관찰, 한Q 수동 스냅샷의 수집, 한Q 종료 관측, 기록 종료 시각.
- `incidents/`: 기록 시작 후 생성된 한Q의 구조화된 처리 메타데이터. 시작 전에 있던 파일은 제외한다. 원래 입력 본문·키 값·클립보드는 없다.
- `result.json`: 종료 여부, 수집 파일/바이트·관찰 수·거절 파일 수·수집 불완전 상태와 관측된 한Q 빌드.

2초마다 파일을 확인한다. 한 구간은 최대128개 진단 파일·64MiB·일반 표시512개로 제한한다. 지원하는 스키마의 필드만 저장하며 알 수 없는 본문/키 필드, 심볼릭 링크, 공개 권한 파일, 4MiB 초과 파일과 교체된 원본 폴더는 거절한다. 로그는 사용자 전용 폴더/파일 권한으로 저장한다. 수집 오류는 일부 기록을 남긴 상태와 구분해 표시한다. 한Q 종료를 감지하면 해당 구간을 끝내고, 다시 시작할 때 실행 중인 한Q를 새로 확인한다.

한Q 자체의 수동·자동 각32구간 한도는 별도로 적용된다. 그 한도를 늘리거나 새로운 키 감시·AX 조회를 추가하지 않는다. 이 기록은 사용자 관찰과 한Q 내부 처리의 근거이며 ChatGPT의 실제 글자 수신·최종 본문·커서를 자동 검증하지 않는다. 기록 없음이나 정상 표시만으로 무손실을 확정하지 않는다. 표시 시각은 수집 앱의 시계이며 진단 프레임은 한Q 내부 상대 시각이므로 연결은 보조적으로 대조한다.

```sh
python3 scripts/summarize-input-test-session.py '<세션 폴더>'
python3 scripts/summarize-input-incident.py '<세션 폴더>'/incidents/*.json
bash scripts/test-input-test-recorder.sh
```

개발자 자체 UI 검사는 `--self-test --output-root <임시 폴더>`로 실행한다. 해당 세션에는 자체 검사임을 명시하며 실제 ChatGPT 시험이나 사용자 관찰로 합산하지 않는다.
