# 긴 본문 입력 확인

설치한 한Q의 새 프로세스에 권한 사전 체크를 마친 뒤 사용한다. 자동 검사와 사람이 누르는 물리 키 검사를 구분한다. 시험창은 합성 본문만 만들며 기존 문서·클립보드를 읽지 않는다.

```sh
bash scripts/test-long-document-input.sh <권한-record.json> <새-자동-결과-폴더>
bash scripts/prepare-long-document-physical.sh <권한-record.json> <새-물리-결과-폴더>
```

자동 검사는 전용 AppKit 입력창에 보호된 합성 HID 키를 보낸다. 1만 자 문맥의 문장 연속 입력(40·20·8ms 목표 간격), 다섯 한국어 배열, 첫 자음 관측 실패·영문 불일치 주입, 빠른 왕복 전환·전체 선택·삭제·선택 영타 변환을 검사한다. 본문 전체의 UTF-16 일치·커서·입력 소스·실제 전달 개수와 복구 재입력 관측을 기록한다. 지연은 마지막 합성 키 전송 뒤 최종 결과를 처음 확인한 시간이며, 모든 물리 키의 처리 지연을 뜻하지 않는다. 실패하면 다음 단계로 진행하지 않고 원래 입력 소스를 복원한다. 제품 종료·포커스·보안 입력·권한 변화에는 전송을 멈춘다.

자동 입력 직전과 결과 확인 직후에는 시험창에 포커스를 유지한 채 제품의 활성 감시 탭 6개(HID 2·session 3·annotated 1)를 확인한다. 권한·프로세스 생존만으로 감시가 정상이라고 판단하지 않는다. 시험창을 닫은 뒤 대상 탭을 다시 연결하는 과도 상태는 이 검사와 구분한다. 준비 대기는 입력 측정에서 제외한다.

원래 키의 `keyDown` 진입·처리 반환 시각은 각각 최대 1,500개를 기록하고, 초과는 `receiverTimingClipped`로 표시한다. 원래 키 개수·순서가 합성 전송과 일치하고 잘리지 않은 일반 연속 입력에서만 두 배열을 순서대로 대응한다. 전송 직전부터 수신까지의 대기, `keyDown` 내부 처리, 마지막 키부터 전체 결과 확인까지의 시간을 구분한다. 수신 전 대기에는 상위 탭·AppKit 전달·IME·AX 서비스·스케줄링 등이 포함될 수 있어 한Q 콜백 비용으로 단정하지 않는다. 기존 `confirmAfterLastPostMs`의 기준은 마지막 key-up까지 마친 sender 완료 시각이며, 마지막 key-down 기준과 혼용하지 않는다. 시각 배열에는 키 값·본문을 담지 않으며 합성 전송과 수신은 같은 단조 시계를 사용한다. 물리 키 지연 검사는 아니다.

탭 확인에 사용하는 `CGGetEventTapList`의 지연 통계도 기록한다. 이 API는 조회할 때 최소·최대 값을 평균값으로 재설정하고, 다른 관측자의 조회도 구간에 영향을 준다. 같은 `tapID`의 전후 스냅샷을 대조하되 누적 최대·개별 키 지연·콜백 처리 시간의 확정값으로 해석하지 않는다. 이 통계는 입력 결과나 지연 판정을 대신하지 않는다.

물리 키 준비 명령은 창만 열고 대기한다. 키를 전송하거나 단계를 자동 실행하지 않는다. 실행별 임시 위치는 결과 폴더의 `stage.txt`에 남기며 시험 앱은 그 위치에만 메타데이터 결과를 쓴다.

1. 내장/외부 키보드를 고르고 ‘단계 시작’을 누른다. ‘입력 준비 완료’를 기다린다.
2. 창의 안내대로 직접 타자한다. 연속 문장은 마침표 뒤 공백 한 개까지 입력한다. 붙여넣기나 입력 오류의 사후 수정은 하지 않는다.
3. ‘입력 완료 확인’을 누른다. 400ms 간격의 두 조회에서 본문 전체·커서와 추가 키 유무를 대조하고 마지막 입력 소스를 확인한 뒤 다음 단계로 이동한다. 모든 중간 시점을 연속 관측하거나 키별 지연을 측정하는 검사는 아니다.
4. 불일치하면 창을 유지하고 한Q 메뉴의 ‘진단 및 로그 → 방금 발생한 문제 기록’을 누른다. 잘못 누른 키가 있었다면 함께 기록한다. 다시 시도해도 이전 실패는 남는다.
5. 마지막 단계 완료 또는 ‘종료·원래 소스 복원’으로 원래 입력 소스를 복원한다. 시험 중 다른 앱을 편집하지 않는다.

물리 키 8단계는 1천/1만 자 연속 문장, 빠른 한영 왕복, 전체 선택 뒤 전환·대체, 강제 영문 불일치 복구, 복구 직후 전환, 삭제 뒤 재입력·전환, 선택 영타 변환 뒤 첫 전환이다. 영문 주입 단계는 자연 발생 버그의 빈도를 검증하지 않는다. 사람의 시험 결과·체감 지연과 실제 TextEdit·브라우저 등 앱별 실사용 결과는 별도로 보고한다. 시험창 성공만으로 다른 앱의 확인을 통과 처리하지 않는다.

마지막 단계는 ‘싸이월드’ 변환을 눈으로 확인한 직후 첫 한영 전환을 검사한다. 변환 요청이 아직 끝나기 전에 전환하는 별도 조건과 구분한다. 강제 복구 직후 전환 단계도 실제 복구 작업과 전환이 시간상 겹쳤다는 증명으로 세지 않는다.

합성 삭제 키에는 macOS backward-delete의 U+007F를 명시한다. 한Q 없는 네이티브 대조에서 이 합성 경로는 `간` 전체가 지워진 뒤 `ㅁ`이 입력돼, 자동 삭제 시험은 그 조건의 `ㅁabc`를 확인한다. 물리 키의 조합 중 `간 → 가 → 감`은 별도 확인한다. 글자 단위 삭제 결과나 오류 주입 미실행은 입력 실패와 구분해 기록하며, 미확인 조건을 통과로 세지 않는다.

선택 변환은 전체 합성 본문·10자 선택·영문 소스가 120ms 유지되는 것을 확인한 뒤 변환키와 즉시 전환을 보낸다. 마지막 전송 뒤 결과 확인 시간은 준비 대기를 제외하며, 전체 `sendToStableMs`에는 준비 대기도 포함된다. 개별 키의 지연이나 입력 소스 준비 완료 시간으로 해석하지 않는다. `HANQ_LONG_SINGLE_PARAGRAPH=1`은 줄바꿈 없는 문맥, `HANQ_LONG_NORMAL_ONLY=1`은 연속 문장 3조건, `HANQ_LONG_RECOVERY_ONLY=1`은 독립 입력기·복구·전환 12조건을 고른다. 결과의 `plannedCases`와 본문 형태를 함께 보고하며 그룹 성공을 전체 성공으로 확대하지 않는다.

키 전송과 입력 소스 변경은 모두 전역 동작이므로 다른 앱에서 타자하지 않는 전용 시험 시간을 사용한다. 명령행 보호 도구는 AppKit을 비활성 상태로 초기화하고, 매 키 전송과 소스 변경 직전에 시스템 AX의 실제 키보드 포커스 소유 PID를 새로 확인한다. 전면 앱·보안 입력·권한·소유 프로세스 경로/시작 식별도 검사한다. 소스 변경은 이 검사를 통과한 별도 프로세스로 요청하며, 시험 앱의 내부 포커스만으로 허용하지 않는다.

포커스를 잃으면 키 전송을 중단한다. 소스 복원도 다른 앱에서 자동 실행하지 않으며, 복원이 필요한 시험창으로 돌아와 ‘이 창에서 원래 입력 소스 복원 후 종료’를 눌러야 한다. 복원 후에도 원래 실패 결과는 실패로 남는다. 시험 도구는 이전 앱을 다시 활성화하지 않는다. 사용자 기존 소스를 비활성화하지 않고 시험에서 추가로 활성화한 소스만 복원한다.

`bash scripts/test-long-document-source-guards.sh`는 소유/포커스/보안/권한/요청 시각과 포커스 상실 후 복원 보류를 기본·최적화 컴파일에서 검사한다. 실제 키나 입력 소스를 바꾸지 않는 대역 검사다. `bash scripts/build-long-document-fixture.sh <새-캐시>`로 미리 만든 도구는 `HANQ_LONG_FIXTURE_CACHE`로 사용할 수 있다. 컴파일 전 소스 해시와 실행 파일 해시를 고정하고 사용 직전에 다시 대조하므로 변경된 소스를 오래된 도구로 시험하지 않는다.

목표 입력 간격과 실제 전송 간격을 함께 보고한다. 매 키의 동기 AX 안전 확인은 전송 간격을 늘릴 수 있으므로, 보호 도구가 다른 이전 결과와 마지막 전송 이후 지연만 직접 비교하지 않는다. 같은 도구의 수정 전 대조와 실제 전송 간격이 필요하다. `trial-end.json`은 입력 검증 종료 시각을 소스 복원 전에 기록한다. CPU는 이 경계 안에서 측정하고 준비·예열·소스 복원·사건 캡처 구간은 구분한다.

`HANQ_LONG_MANUAL_SWITCH_GAP_MS=0..200`은 선택 영타 변환 조건의 변환키와 첫 전환키 사이 목표 간격을 지정한다. `conversionDownToSwitchDownMs`와 전송 시각 표본은 매 키 안전 확인이 끝난 뒤 실제 `post` 직전의 단조 시각으로 계산한다. 붙여넣기 수신·처리 시각과 `switchPostedBeforePasteHandled`를 함께 확인해, 변환 완료 전 요청이 실제로 겹쳤는지 구분한다. 실패의 5초 확인 시간초과는 실제 처리 지연으로 해석하지 않는다.

`HANQ_LONG_RESULT_HOLD_SECONDS=0..2`는 결과를 기록한 뒤 같은 소유 입력창을 잠시 유지하는 관측용 옵션이다. 결과 지연에는 포함하지 않는다. 이를 이용한 고정 길이 CPU 관측도 실제 요청 전 준비 시각과 첫 CPU 표본 사이의 간격, 사건 캡처 겹침을 따로 기록한다. 준비 단계에서 안전 중단된 결과는 입력 시험 성공이나 제품 입력 실패로 합산하지 않는다.

`HANQ_LONG_CASES`는 정확한 조건 이름의 JSON 배열로 독립 조건 일부를 선택한다. 중복·알 수 없는 이름·빈 목록은 거부하며, 원래 정의 순서를 유지한다. 결과의 `plannedCases`와 실제 실행 목록을 대조한다. 안전하게 복원된 준비 중단 뒤 남은 독립 조건을 새 창에서 확인하더라도, 앞선 중단 결과는 통과로 바꾸지 않는다. 실제 입력 결과 실패를 이 기능으로 재시도해 성공만 남기지 않는다.

소스 보조 도구는 `source-control-status.json`에 소유/포커스/보안/권한/기한의 불리언과 고정 AX 실패 사유·상태를 남긴다. 실패 관측·명령은 각각 최대 16개이며, 입력 본문·키·외부 포커스 내용은 기록하지 않는다. 포커스 사유는 1 PID, 2 권한, 3 보안 입력, 4 전면 소유자, 5 AX 조회 상태, 6 AX 값 종류, 7 AX 소유 PID 조회 상태, 8 다른 키보드 포커스 소유자다. 일시적 `AXError.cannotComplete`이고 나머지 조건을 모두 통과한 경우에만 10ms 뒤 전체 안전 조건을 한 번 새로 확인한다. 이전 증거·새 기한·추가 재시도를 허용하지 않으며, 실제 TIS 변경 직전에도 원래의 재검증을 유지한다. 매 키 전송의 포커스 거부에는 이 재시도를 적용하지 않는다.
